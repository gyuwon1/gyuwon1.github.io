스위치 하나에 연결된 장치는 기본적으로 모두 같은 브로드캐스트 도메인에 있다. VLAN은 스위치 한 대를 논리적으로 여러 개의 독립된 네트워크로 나누는 기능이다.

## 왜 VLAN이 필요한가

Day 12에서 본 것처럼 브로드캐스트는 같은 VLAN의 모든 포트로 플러딩된다. 장치가 늘어날수록 브로드캐스트가 많아져 모든 장치가 불필요한 프레임을 처리하게 된다. 부서가 다른 장치들이 같은 망에 섞여 있으면 보안 관리도 어렵다.

물리적으로 나누려면 부서마다 스위치를 따로 두어야 한다. VLAN을 쓰면 스위치 한 대로 포트별로 소속만 정해서 같은 효과를 낸다.

![VLAN이 없을 때는 브로드캐스트가 모든 PC에 도달하고, VLAN 10과 20으로 나누면 같은 VLAN에만 도달하는 비교]({{ '/assets/img/ccna/day13-broadcast-domain.svg' | relative_url }})

VLAN을 나누면 얻는 것은 세 가지다.

- 브로드캐스트 도메인이 작아져 불필요한 트래픽이 줄어든다
- 부서나 용도별로 망을 분리해 보안 정책을 적용하기 쉽다
- 장치의 물리적 위치와 상관없이 포트 설정만으로 소속을 바꿀 수 있다

## VLAN의 기본 규칙

- VLAN은 번호(ID)로 구분하며 범위는 1~4094다. 1~1005는 정상 범위, 1006~4094는 확장 범위다
- 모든 포트는 처음에 VLAN 1(default)에 속해 있다. VLAN 1은 삭제할 수 없다
- 1002~1005는 예전 기술용으로 예약된 VLAN이라 지울 수 없다
- 보통 VLAN 하나에 IP 서브넷 하나를 대응시킨다. 위 그림의 VLAN 10은 192.168.10.0/24, VLAN 20은 192.168.20.0/24 같은 식이다
- 다른 VLAN끼리는 스위치만으로 통신할 수 없다. 서로 통신하려면 라우팅이 필요하며 Day 15에서 다룬다

## 액세스 포트

PC 같은 단말이 연결되는 포트를 액세스 포트라고 한다. 액세스 포트는 VLAN 하나에만 속하고, 단말은 VLAN을 의식하지 않고 일반 이더넷 프레임을 주고받는다. 스위치가 포트에 지정된 VLAN으로 프레임을 분류한다.

![Fa0/1, Fa0/2는 VLAN 10, Fa0/3, Fa0/4는 VLAN 20에 할당된 스위치에서 같은 VLAN끼리만 통신이 되는 구성]({{ '/assets/img/ccna/day13-port-vlan.svg' | relative_url }})

PC-A와 PC-B는 같은 VLAN 10이라 통신된다. PC-A에서 PC-C로는 ping이 되지 않는다. 서브넷도 다르고 VLAN도 다르기 때문이다.

스위치가 여러 대일 때 VLAN을 스위치 사이로 확장하는 방법은 다음 글(Day 14)의 트렁크에서 다룬다.

## 설정

VLAN을 만들고 이름을 붙인 뒤, 포트를 액세스 모드로 바꾸고 VLAN에 할당한다.

```
SW1# configure terminal
SW1(config)# vlan 10
SW1(config-vlan)# name SALES
SW1(config-vlan)# vlan 20
SW1(config-vlan)# name ENG
SW1(config-vlan)# exit

SW1(config)# interface range fa0/1 - 2
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 10
SW1(config-if-range)# exit

SW1(config)# interface range fa0/3 - 4
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 20
SW1(config-if-range)# end
```

- `vlan 10`은 VLAN을 만들고 VLAN 설정 모드로 들어간다. `name`은 생략해도 되며, 생략하면 VLAN0010 같은 이름이 붙는다
- `interface range`는 여러 포트를 한 번에 설정한다
- `switchport mode access`는 포트를 액세스 포트로 고정한다
- `switchport access vlan 10`은 포트를 VLAN 10에 넣는다

## 확인 명령

```
SW1# show vlan brief

VLAN Name                             Status    Ports
---- -------------------------------- --------- -------------------------------
1    default                          active    Fa0/5, Fa0/6, Fa0/7, Fa0/8
10   SALES                            active    Fa0/1, Fa0/2
20   ENG                              active    Fa0/3, Fa0/4
1002 fddi-default                     act/unsup
1003 token-ring-default               act/unsup
1004 fddinet-default                  act/unsup
1005 trnet-default                    act/unsup

SW1# show interfaces fa0/1 switchport
SW1# show mac address-table
```

- `show vlan brief`로 VLAN별 이름, 상태, 소속 포트를 한 번에 본다. 위 출력은 포트가 8개인 스위치를 가정한 예다
- `show interfaces fa0/1 switchport`는 포트의 모드(access)와 소속 VLAN을 보여 준다
- `show mac address-table`의 Vlan 열에는 학습된 MAC이 어느 VLAN에 속하는지 나온다. Day 12에서 MAC 주소 테이블이 VLAN별로 관리된다고 한 이유다

## 주의할 점

- 포트를 VLAN에 넣기 전에 VLAN을 먼저 만든다. VLAN이 없는 번호를 쓰면 포트가 정상 동작하지 않는다
- `no vlan 10`으로 VLAN을 지우면 그 VLAN에 속했던 포트는 VLAN 1로 돌아가지 않고 inactive 상태가 된다. 지우기 전에 포트를 다른 VLAN으로 옮긴다
- 정상 범위 VLAN 정보는 플래시의 vlan.dat 파일에 저장된다. 그래서 running-config를 저장하지 않고 재부팅해도 VLAN 자체는 남는다

## 확인 문제

1. VLAN을 나누면 어떤 도메인이 작아지는가?
2. 모든 포트가 처음에 속해 있는 VLAN은 몇 번이며, 삭제할 수 있는가?
3. 포트를 VLAN 20의 액세스 포트로 만드는 인터페이스 설정 명령 두 줄을 쓰라.
4. VLAN별 이름, 상태, 소속 포트를 한 화면에서 확인하는 명령은?
5. 서로 다른 VLAN에 있는 두 PC는 스위치 하나만으로 통신할 수 있는가?
