네트워크가 커지면 케이블 반대편에 어떤 장비가 어느 포트로 연결되어 있는지 알기 어려워진다. CDP와 LLDP는 장비가 자기 정보를 이웃에게 알리고, 이웃의 정보를 받아 두는 Layer 2 프로토콜이다.

## 이웃 탐색

![SW1, SW2, SW3이 일렬로 연결된 구성에서 각 장비의 이웃 목록에 직접 연결된 장비만 나오는 그림]({{ '/assets/img/ccna/day19-neighbors.svg' | relative_url }})

장비는 일정 주기로 자기 정보가 담긴 프레임을 멀티캐스트로 내보낸다. 받은 장비는 그 정보를 이웃 테이블에 저장하고 프레임을 더 전달하지 않는다. 그래서 이웃은 케이블로 직접 연결된 장비로 한정된다. 두 프로토콜 모두 Layer 2에서 동작하므로 IP 주소를 설정하기 전에도 쓸 수 있다.

이웃 테이블에서 얻는 정보는 다음과 같다.

- 이웃의 장비 이름
- 내 쪽 포트와 상대 쪽 포트
- 장비 종류(스위치, 라우터 등)와 모델
- 관리용 IP 주소

배선 확인, 장애 위치 추적, 구성도 작성에 쓴다.

## CDP와 LLDP 비교

![CDP와 LLDP의 규격, 목적지 MAC, 전송 주기, 홀드타임, Cisco 기본값을 비교한 표]({{ '/assets/img/ccna/day19-compare.svg' | relative_url }})

CDP(Cisco Discovery Protocol)는 Cisco 전용이다. Cisco 장비에서는 기본으로 켜져 있다. LLDP(Link Layer Discovery Protocol)는 IEEE 802.1AB 표준이라 제조사가 달라도 쓸 수 있다. Cisco IOS에서는 기본으로 꺼져 있어 직접 켜야 한다. 상대가 Cisco가 아니거나 IP 전화기, 서버 같은 단말이 섞여 있으면 LLDP를 쓴다.

## 광고되는 정보

![CDP 프레임과 LLDP 프레임에 들어가는 항목을 나란히 보여주는 그림]({{ '/assets/img/ccna/day19-tlv.svg' | relative_url }})

두 프로토콜 모두 TLV(Type, Length, Value) 단위로 정보를 담는다. 이름은 다르지만 역할은 비슷하다. 장비 식별자(Device ID, Chassis ID), 포트 식별자(Port ID), 유지 시간(Holdtime, TTL), 기능(Capabilities), 관리 주소가 들어간다. 수신한 장비는 유지 시간 안에 같은 이웃의 새 프레임이 오지 않으면 그 항목을 테이블에서 지운다. 케이블을 뽑고 한참 뒤에 이웃 정보가 사라지는 것은 이 때문이다.

## CDP 설정과 확인

```
SW1# show cdp neighbors
SW1# show cdp neighbors detail
SW1# show cdp
```

`show cdp neighbors`는 이웃을 한 줄씩 보여준다. 로컬 인터페이스, 홀드타임, 기능, 플랫폼, 상대 포트가 나온다. `detail`을 붙이면 상대의 IP 주소와 IOS 버전까지 나온다.

켜고 끄는 명령은 두 단계로 나뉜다.

```
SW1(config)# no cdp run
SW1(config)# cdp run
SW1(config)# interface gigabitEthernet 0/1
SW1(config-if)# no cdp enable
```

`no cdp run`은 장비 전체에서 CDP를 끈다. `no cdp enable`은 해당 인터페이스에서만 끈다. 주기와 유지 시간은 `cdp timer`와 `cdp holdtime`으로 바꾼다.

## LLDP 설정과 확인

```
SW1(config)# lldp run
SW1(config)# interface gigabitEthernet 0/1
SW1(config-if)# no lldp transmit
SW1(config-if)# no lldp receive
```

`lldp run`으로 장비 전체에서 켠다. 인터페이스에서는 송신(`lldp transmit`)과 수신(`lldp receive`)을 따로 켜고 끈다. 주기와 유지 시간은 `lldp timer`와 `lldp holdtime`으로 바꾼다. 확인 명령은 CDP와 같은 형태다.

```
SW1# show lldp neighbors
SW1# show lldp neighbors detail
SW1# show lldp
```

IP 전화기에는 LLDP를 확장한 LLDP-MED를 쓴다. 전화기에게 음성 VLAN 번호를 알려 주는 용도로 쓰인다. 두 프로토콜을 동시에 켜 두는 것도 가능하다.

## 보안

광고 프레임에는 장비 모델, 소프트웨어 버전, 관리 IP가 들어 있다. 이 정보는 공격자가 장비를 파악하는 데 도움이 된다. 사용자 PC나 외부와 연결된 포트에서는 CDP와 LLDP를 끄는 것이 일반적이다. 장비 사이의 링크에서만 켜 둔다.

## 확인 문제

1. CDP로 알 수 있는 이웃 장비는 어디까지인가?
2. CDP와 LLDP 중 Cisco 전용인 것은 무엇이고, Cisco IOS에서 기본으로 꺼져 있는 것은 무엇인가?
3. 특정 인터페이스에서만 CDP를 끄는 명령은 무엇인가?
4. 이웃의 IP 주소와 IOS 버전까지 보려면 어떤 명령을 쓰는가?
5. 사용자 PC가 연결된 포트에서 CDP와 LLDP를 끄는 이유는 무엇인가?

<details>

1. 케이블로 직접 연결된 장비까지이다. 광고 프레임은 다음 장비로 전달되지 않는다.
2. Cisco 전용은 CDP이고, 기본으로 꺼져 있는 것은 LLDP이다. LLDP는 `lldp run`으로 켠다.
3. 해당 인터페이스에서 `no cdp enable`을 입력한다. 장비 전체에서 끄는 명령은 `no cdp run`이다.
4. `show cdp neighbors detail`을 쓴다.
5. 광고 프레임에 모델, 소프트웨어 버전, 관리 IP 같은 정보가 들어 있어 공격자가 장비를 파악하는 데 쓸 수 있기 때문이다.
