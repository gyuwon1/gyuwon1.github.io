어제 본 OSPF 개념을 장비에 옮긴다. 오늘은 기본 설정 순서, network 명령의 와일드카드 마스크, 자주 쓰는 확인 명령, 이웃이 안 맺어질 때 보는 순서를 다룬다.

## 기본 설정

![R1과 R2가 10.0.12.0/30 링크로 연결되고 각자 사용자 LAN을 가지며 두 라우터가 모두 Area 0에 속하는 구성도와 설정 명령]({{ '/assets/img/ccna/day25-topology.svg' | relative_url }})

설정은 라우터 프로세스를 만들고, 라우터 ID를 정하고, 어떤 인터페이스를 어느 영역에 넣을지 알려주는 순서이다.

```
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# passive-interface GigabitEthernet0/1
```

- `router ospf 1`의 1은 프로세스 ID이다. 라우터 안에서만 의미가 있어서 라우터마다 달라도 이웃을 맺는 데 문제가 없다
- `router-id`는 직접 지정하는 것이 좋다. 이미 OSPF가 돌고 있는 상태에서 바꾸면 `clear ip ospf process`를 해야 적용된다
- `network 주소 와일드카드 area 번호`는 그 범위에 들어오는 IP를 가진 인터페이스에서 OSPF를 켠다. 광고되는 것은 범위가 아니라 그 인터페이스의 실제 서브넷이다
- `passive-interface`는 해당 인터페이스로 Hello를 보내지 않는다. 사용자 LAN처럼 다른 라우터가 없는 곳에 쓰고, 그 서브넷은 계속 광고된다

인터페이스 안에서 `ip ospf 1 area 0`으로 직접 켜는 방법도 있다. 이 방법은 와일드카드 계산이 필요 없다.

## 와일드카드 마스크

network 명령의 두 번째 값은 서브넷 마스크가 아니라 와일드카드 마스크이다. 255.255.255.255에서 서브넷 마스크를 뺀 값이고, 비트 0은 반드시 일치해야 하는 자리, 비트 1은 무시하는 자리이다.

![서브넷 마스크 255.255.255.252, 255.255.255.0, 255.255.255.255를 와일드카드 0.0.0.3, 0.0.0.255, 0.0.0.0으로 바꾸고 마지막 옥텟의 비트를 비교한 그림]({{ '/assets/img/ccna/day25-wildcard.svg' | relative_url }})

인터페이스 IP가 10.0.12.1이면 `10.0.12.0 0.0.0.3` 범위(10.0.12.0~10.0.12.3)에 들어가므로 OSPF가 켜진다. 호스트 하나만 지정하려면 와일드카드를 0.0.0.0으로 쓴다.

## 비용 조정

OSPF 비용은 기준 대역폭을 인터페이스 대역폭으로 나눈 값이고 최소값은 1이다. 기본 기준 대역폭은 100Mbps이다. 그래서 FastEthernet(100Mbps)과 GigabitEthernet(1Gbps)이 모두 비용 1이 되어 두 링크를 구별하지 못한다. 기준 대역폭을 올려 해결한다.

```
R1(config-router)# auto-cost reference-bandwidth 10000
```

단위는 Mbps이다. 10000으로 올리면 1Gbps는 비용 10, 100Mbps는 100, 10Gbps는 1이 된다. 라우터마다 값이 다르면 경로 선택이 어긋나므로 모든 라우터에 같은 값을 넣는다. 한 인터페이스만 바꾸려면 `ip ospf cost 값`을 쓴다.

## 그 밖의 설정

- `ip ospf priority 값`: DR 선출 우선순위를 바꾼다. 0이면 DR 후보에서 빠진다
- `ip ospf network point-to-point`: 이더넷 링크에 라우터가 두 대뿐일 때 쓴다. DR 선출을 건너뛰어 이웃이 빨리 Full이 된다. 양쪽 모두 같은 값이어야 한다
- `ip ospf hello-interval`, `ip ospf dead-interval`: 타이머를 바꾼다. 양쪽이 같아야 이웃이 맺어진다
- `default-information originate`: 라우터가 가진 디폴트 라우트를 OSPF로 알린다. 라우팅 테이블에 디폴트 라우트가 있어야 광고된다

## 확인 명령

| 명령 | 보는 것 |
|------|---------|
| `show ip ospf neighbor` | 이웃 목록, 상태, Dead 시간 |
| `show ip ospf interface brief` | OSPF가 켜진 인터페이스, 영역, 비용, 이웃 수 |
| `show ip ospf interface` | Hello와 Dead 타이머, DR과 BDR, 네트워크 타입 |
| `show ip route ospf` | OSPF로 배운 경로 |
| `show ip protocols` | 라우터 ID, network 문, passive 인터페이스, AD |
| `show ip ospf` | 라우터 ID, 영역, SPF를 돌린 횟수 |
| `show ip ospf database` | LSDB 내용 |

이웃 상태는 다음처럼 나온다.

```
R1# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/DR         00:00:33    10.0.12.2       GigabitEthernet0/0
```

State의 FULL/DR은 상대가 이 세그먼트의 DR이고 인접이 완성되었다는 뜻이다. 점대점 링크에서는 `FULL/  -`로 나온다. Dead Time은 Hello를 받을 때마다 40초로 되돌아가므로 30~40초 사이를 오르내리면 정상이다.

인터페이스 요약과 경로는 이렇게 보인다.

```
R1# show ip ospf interface brief
Interface    PID   Area            IP Address/Mask    Cost  State Nbrs F/C
Gi0/0        1     0               10.0.12.1/30       1     BDR   1/1
Gi0/1        1     0               192.168.1.1/24     1     DR    0/0

R1# show ip route ospf
O    192.168.2.0/24 [110/2] via 10.0.12.2, 00:05:12, GigabitEthernet0/0
```

Nbrs F/C는 Full 상태 이웃 수와 전체 이웃 수이다. Gi0/1은 passive라서 이웃이 없고 혼자라 DR로 표시된다. 경로 앞의 O는 OSPF 경로이고, 대괄호의 110은 AD, 2는 비용이다. 링크 비용 1에 R2의 LAN 인터페이스 비용 1이 더해졌다. 다른 영역에서 온 경로는 `O IA`로 표시된다.

## 이웃이 안 맺어질 때

![이웃 목록 없음, Init 정지, ExStart와 Exchange 정지, Full인데 경로 없음의 네 증상별로 확인할 명령과 의심할 원인을 이은 그림]({{ '/assets/img/ccna/day25-verify.svg' | relative_url }})

Day 24의 이웃 조건이 그대로 점검표가 된다. 먼저 `show ip ospf interface`로 양쪽의 영역, Hello와 Dead 값, 서브넷, passive 여부를 나란히 비교한다. 이웃 목록에 아예 없으면 이 값 중 하나가 어긋난 경우가 많다. 상태가 ExStart나 Exchange에서 멈추면 MTU를 의심한다. 이웃이 Full인데 경로가 없으면 상대 라우터의 network 문이 그 망을 포함하는지 본다. 이더넷 세그먼트에서 DROther끼리 2-Way로 남는 것은 정상이다.

## 확인 문제

1. 192.168.1.0/24 망의 인터페이스를 Area 0에 넣는 network 명령을 쓰시오.
2. 사용자 LAN 쪽 인터페이스에서 Hello를 막으면서 그 망은 계속 광고하려면 어떤 명령을 쓰는가?
3. R1은 `router ospf 1`, R2는 `router ospf 10`으로 설정했다. 이웃을 맺을 수 있는가?
4. 기본 설정에서 FastEthernet과 GigabitEthernet의 OSPF 비용은 각각 얼마이고, 이를 구별하게 하려면 어떻게 하는가?
5. 이웃 상태가 ExStart에서 멈췄다. 가장 먼저 의심할 것은 무엇인가?

<details>
<summary>정답 보기</summary>

1. `network 192.168.1.0 0.0.0.255 area 0`이다.
2. `passive-interface 인터페이스이름`이다.
3. 맺을 수 있다. 프로세스 ID는 라우터 안에서만 의미가 있다.
4. 둘 다 1이다. `auto-cost reference-bandwidth 10000`처럼 기준 대역폭을 올리고 모든 라우터에 같은 값을 넣는다.
5. 양쪽 인터페이스의 MTU 불일치이다.
