## 계층 모델

통신 과정을 계층으로 나누어 놓은 것이 네트워크 모델이다. 계층마다 맡는 일이 정해져 있어서 장애가 났을 때 어느 계층 문제인지 좁혀 갈 수 있고, 한 계층을 바꿔도 다른 계층은 영향을 받지 않는다. 대표적인 모델은 OSI 7계층과 TCP/IP 4계층이다. 실제 장비와 프로토콜은 TCP/IP 기준으로 만들어져 있고, OSI는 설명과 시험에서 계층 번호를 말할 때 쓴다.

![OSI 7계층과 TCP/IP 4계층 대응]({{ '/assets/img/ccna/day2-osi-tcpip.svg' | relative_url }})

## OSI 7계층

아래에서 위로 1계층부터 센다.

| 계층 | 이름 | 역할 | 데이터 단위 |
|------|------|------|-------------|
| 7 | 응용 | 사용자가 쓰는 서비스 (웹, 메일, 이름 조회) | 데이터 |
| 6 | 표현 | 데이터 형식 변환, 암호화, 압축 | 데이터 |
| 5 | 세션 | 통신 연결의 시작과 유지, 종료 | 데이터 |
| 4 | 전송 | 프로세스 간 전달, 포트 번호, 신뢰성 | 세그먼트 |
| 3 | 네트워크 | IP 주소, 경로 선택 | 패킷 |
| 2 | 데이터 링크 | MAC 주소, 같은 네트워크 안의 전달 | 프레임 |
| 1 | 물리 | 전기·빛·전파 신호, 케이블, 커넥터 | 비트 |

장비와 연결해 보면 라우터는 3계층, 스위치는 2계층에서 동작한다. 허브나 케이블은 1계층이다. "L3 스위치"는 스위치 기능에 라우팅 기능이 더해진 장비다.

## TCP/IP 4계층

TCP/IP는 OSI의 5~7계층을 응용 계층 하나로 묶고, 1~2계층을 네트워크 접근 계층으로 묶는다.

- 응용: HTTP, DNS, DHCP, SSH 같은 프로토콜
- 전송: TCP, UDP
- 인터넷: IP, ICMP
- 네트워크 접근: 이더넷, Wi-Fi

교재에 따라 네트워크 접근 계층을 데이터 링크와 물리로 나눈 5계층 모델로 설명하기도 한다. 계층 번호를 물으면 OSI 번호로 답한다.

## 캡슐화

데이터를 보낼 때는 위 계층에서 아래 계층으로 내려가며 계층마다 자기 정보를 담은 헤더를 앞에 붙인다. 이것이 캡슐화다.

![캡슐화 과정]({{ '/assets/img/ccna/day2-encapsulation.svg' | relative_url }})

- 전송 계층: TCP 헤더를 붙인다. 출발지와 목적지 포트 번호가 들어 있다. 여기까지가 세그먼트다.
- 네트워크 계층: IP 헤더를 붙인다. 출발지와 목적지 IP 주소가 들어 있다. 여기까지가 패킷이다.
- 데이터 링크 계층: 이더넷 헤더를 앞에, FCS를 뒤에 붙인다. 헤더에는 출발지와 목적지 MAC 주소가 들어 있고, FCS는 전송 중 데이터가 깨졌는지 검사하는 값이다. 여기까지가 프레임이다.
- 물리 계층: 프레임을 비트로 바꿔 신호로 내보낸다.

받는 쪽에서는 반대로 아래에서 위로 올라가며 계층마다 자기 헤더를 읽고 벗겨 낸다. 이것이 역캡슐화다. 각 계층은 같은 계층의 헤더만 읽는다. 스위치는 이더넷 헤더만, 라우터는 IP 헤더까지만 보고 그 위의 데이터 내용은 보지 않는다.

## 라우터를 지날 때

주소의 종류마다 쓰이는 범위가 다르다. 포트 번호는 호스트 안의 어떤 프로그램인지, IP 주소는 최종 목적지가 어디인지, MAC 주소는 바로 다음 장비가 무엇인지를 나타낸다.

![라우터를 지나는 프레임]({{ '/assets/img/ccna/day2-router-hop.svg' | relative_url }})

PC가 다른 네트워크의 서버로 보낼 때 프레임의 도착 MAC은 서버가 아니라 라우터다. 라우터는 받은 프레임에서 이더넷 헤더를 벗기고, IP 헤더의 목적지 주소를 보고 경로를 정한 뒤, 다음 구간용 이더넷 헤더를 새로 붙여 내보낸다. 구간마다 MAC 주소는 바뀌고 IP 주소는 끝까지 유지된다.

## 패킷 캡처로 확인하기

Wireshark로 패킷을 캡처하면 상세 창에 계층 구조가 아래 순서로 보인다.

```
Frame            물리 계층에서 받은 프레임 전체 정보
Ethernet II      출발지·목적지 MAC 주소
Internet Protocol Version 4   출발지·목적지 IP 주소
Transmission Control Protocol 출발지·목적지 포트 번호
Hypertext Transfer Protocol   응용 데이터
```

위에서 아래로 갈수록 안쪽 헤더다. 캡슐화 구조를 그대로 보여 주므로 이 그림과 비교해 보면 이해가 빠르다.
