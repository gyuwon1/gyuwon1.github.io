회선이 막히면 모든 패킷이 똑같이 느려진다. QoS(Quality of Service)는 트래픽 종류에 따라 처리 순서와 대우를 달리해서, 음성처럼 지연에 약한 트래픽을 먼저 보내는 기술이다.

## 네 가지 지표

QoS 문제는 대역폭, 지연, 지터, 손실 네 가지로 나타난다.

![같은 간격으로 보낸 패킷 5개가 도착할 때 지연이 생기고 도착 간격이 달라지며 4번 패킷이 사라지는 그림]({{ '/assets/img/ccna/day31-metrics.svg' | relative_url }})

| 지표 | 뜻 | 커지면 생기는 일 |
|------|-----|------------------|
| 대역폭 | 단위 시간에 보낼 수 있는 양 | 부족하면 큐가 쌓인다 |
| 지연 | 패킷이 도착하기까지 걸리는 시간 | 통화에서 말이 늦게 들린다 |
| 지터 | 지연이 패킷마다 달라지는 정도 | 소리가 끊기거나 일그러진다 |
| 손실 | 도착하지 못하고 사라진 패킷 | 영상이 깨진다 |

음성의 일반적인 목표치는 단방향 지연 150ms 이하, 지터 30ms 이하, 손실 1% 이하이다. 파일 전송이나 메일은 조금 늦어도 문제가 없지만, 음성은 늦으면 바로 품질이 떨어진다. TCP 트래픽은 손실되면 재전송하므로 손실에 견디는 편이고, UDP로 보내는 음성과 영상은 손실이 곧 품질 저하로 이어진다.

QoS가 없으면 회선은 먼저 들어온 순서(FIFO)대로 처리한다. 큰 파일 전송이 큐를 채우고 있으면 뒤에 들어온 음성 패킷도 같이 기다린다.

## 분류와 표시

QoS의 첫 단계는 패킷이 어떤 종류인지 알아내는 분류(classification)이고, 그 결과를 패킷에 적어 두는 것이 표시(marking)이다. 짐에 목적지 태그를 붙여 두면 다음 장소에서는 태그만 보고 처리하는 것과 같다.

![이더넷 프레임의 802.1Q 태그에 있는 CoS 3비트와 IP 헤더 ToS 바이트의 DSCP 6비트, ECN 2비트, 그리고 주요 DSCP 값 표]({{ '/assets/img/ccna/day31-marking.svg' | relative_url }})

표시하는 위치는 두 곳이다.

- CoS: 802.1Q 태그 안의 3비트로 0~7 값을 가진다. 태그가 있는 트렁크에서만 존재하므로 라우터를 지나면 사라진다.
- DSCP: IP 헤더 ToS 바이트의 상위 6비트로 0~63 값을 가진다. IP 헤더에 있어서 경로 전체에 남는다. 하위 2비트는 ECN이다.

DSCP 값은 이름으로 외워 둔다.

- Default(0): 표시 없는 일반 트래픽
- EF(46, 101110): 음성
- AF: AFxy 형태이며 x는 클래스 번호(1~4), y는 폐기 우선순위(1~3)이다. AF41은 34이고 화상 회의에 쓴다. 값은 8x+2y로 계산한다.
- CS: 클래스 셀렉터이다. CS3(24)은 호 설정 같은 신호에 쓴다.

장비가 받은 표시를 믿을지 정하는 경계를 신뢰 경계(trust boundary)라고 한다. 보통 IP 폰이나 접속 스위치까지를 신뢰하고, 그 바깥 PC가 임의로 붙인 표시는 지우거나 다시 표시한다. 그렇지 않으면 누구나 자기 트래픽에 EF를 붙여서 우선권을 가져갈 수 있다.

## 큐잉

분류된 트래픽은 출력 인터페이스에서 큐로 나뉘고, 스케줄러가 어느 큐에서 먼저 꺼낼지 정한다.

![분류기에서 음성 큐, 업무 큐, 기본 큐로 나뉘고 스케줄러가 출력 인터페이스로 꺼내는 흐름]({{ '/assets/img/ccna/day31-queue.svg' | relative_url }})

| 방식 | 동작 |
|------|------|
| FIFO | 들어온 순서대로 보낸다. 기본 동작이다 |
| WFQ | 흐름별로 큐를 나누고 가중치로 공평하게 나눈다 |
| CBWFQ | 클래스별로 대역폭을 보장한다 |
| LLQ | CBWFQ에 엄격 우선 큐를 더한 방식이다. 음성에 쓴다 |

LLQ의 우선 큐는 비어 있지 않으면 항상 먼저 꺼낸다. 그대로 두면 음성이 회선을 독점해 다른 클래스가 굶을 수 있으므로, 우선 큐에는 대역폭 상한이 걸린다. 큐잉은 혼잡해서 큐가 쌓일 때만 효과가 있다. 회선이 비어 있으면 어느 방식이든 차이가 없다.

## 폴리싱과 셰이핑

정해 둔 속도를 넘는 트래픽을 다루는 방식이 둘 있다.

| 구분 | 폴리싱 | 셰이핑 |
|------|--------|--------|
| 초과분 | 버리거나 낮은 등급으로 다시 표시한다 | 버퍼에 담았다가 늦게 보낸다 |
| 지연 | 늘리지 않는다 | 늘어난다 |
| 방향 | 입력과 출력 모두 | 출력만 |
| 용도 | 속도 제한 | 통신사와 약속한 속도에 맞춰 보내기 |

큐가 가득 차서 들어오는 패킷을 모두 버리는 방식을 테일 드롭이라고 한다. 이때 여러 TCP 연결이 동시에 속도를 줄였다가 동시에 늘리는 문제가 생기는데, 이를 막으려고 큐가 차기 전부터 일부 패킷을 확률적으로 미리 버리는 방식이 WRED이다.

## 설정과 확인

Cisco IOS에서는 MQC(Modular QoS CLI)의 세 단계로 설정한다. 클래스를 정의하고, 클래스별 동작을 정책으로 묶고, 인터페이스에 적용한다.

```
R1(config)# class-map match-all VOICE
R1(config-cmap)# match dscp ef
R1(config)# class-map match-all BUSINESS
R1(config-cmap)# match dscp af41
R1(config)# policy-map WAN-OUT
R1(config-pmap)# class VOICE
R1(config-pmap-c)# priority percent 20
R1(config-pmap)# class BUSINESS
R1(config-pmap-c)# bandwidth percent 30
R1(config-pmap)# class class-default
R1(config-pmap-c)# fair-queue
R1(config)# interface GigabitEthernet0/1
R1(config-if)# service-policy output WAN-OUT
R1# show policy-map interface GigabitEthernet0/1
```

`priority`는 LLQ의 우선 큐이고 `bandwidth`는 CBWFQ의 보장 대역폭이다. `class-default`는 어느 클래스에도 맞지 않은 나머지 트래픽을 받는다. `show policy-map interface`는 클래스별로 매칭된 패킷 수와 버려진 패킷 수를 보여 준다.

## 확인 문제

1. 음성 트래픽에 일반적으로 요구되는 단방향 지연, 지터, 손실의 목표치는 얼마인가?
2. CoS와 DSCP는 각각 어디에 있으며, 라우터를 지나도 남는 쪽은 어느 것인가?
3. DSCP EF의 10진수 값과 AF41의 10진수 값은 얼마인가?
4. LLQ에서 우선 큐에 대역폭 상한을 두는 이유는 무엇인가?
5. 폴리싱과 셰이핑은 속도를 넘는 트래픽을 어떻게 다르게 처리하는가?
