DHCP와 ARP는 상대를 확인하지 않고 받은 내용을 그대로 믿는다. 같은 LAN에 붙은 공격자는 이 점을 이용해 가짜 DHCP 서버를 세우거나 가짜 ARP 응답을 보낸다. DHCP Snooping과 DAI는 스위치가 이런 패킷을 걸러내는 기능이다.

## 공격 두 가지

- 가짜 DHCP 서버(Rogue DHCP): 공격자가 정상 서버보다 먼저 OFFER를 보내 잘못된 게이트웨이나 DNS를 배포한다. 단말의 통신이 공격자를 거치게 된다
- DHCP 고갈(Starvation): 위조한 MAC 주소로 요청을 계속 보내 서버의 주소 풀을 비운다
- ARP 스푸핑: 공격자가 "게이트웨이의 MAC 주소는 내 것이다"라는 ARP 응답을 보내 다른 호스트의 ARP 테이블을 바꿔 놓는다. ARP에는 인증이 없어서 그대로 받아들여진다

## DHCP Snooping

![PC1이 보낸 DHCP Discover에 대해 정상 서버의 Offer는 trusted 포트로 통과하고 공격자의 Offer는 untrusted 포트에서 버려지는 구성]({{ '/assets/img/ccna/day37-rogue.svg' | relative_url }})

스위치 포트를 trusted와 untrusted로 나눈다. 기본값은 모두 untrusted이다.

- untrusted 포트로 들어온 DHCP 서버 메시지(OFFER, ACK, NAK)는 버린다
- trusted 포트는 정상 DHCP 서버나 그쪽으로 향하는 업링크에만 지정한다
- 클라이언트가 보내는 DISCOVER, REQUEST는 untrusted 포트에서도 통과한다
- untrusted 포트에서는 DHCP 메시지 안의 클라이언트 MAC 주소가 프레임의 출발지 MAC 주소와 같은지도 확인한다 (기본 동작)

```
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10
SW1(config)# interface gigabitethernet 0/1
SW1(config-if)# ip dhcp snooping trust
SW1(config-if)# exit
SW1(config)# interface range fastethernet 0/1 - 24
SW1(config-if-range)# ip dhcp snooping limit rate 15
```

- `ip dhcp snooping`: 기능을 전체에서 켠다
- `ip dhcp snooping vlan 10`: 적용할 VLAN을 정한다. 이 명령이 없으면 동작하지 않는다
- `ip dhcp snooping trust`: 포트를 trusted로 바꾼다
- `ip dhcp snooping limit rate 15`: 초당 DHCP 패킷이 15개를 넘으면 포트를 err-disabled로 만든다. 고갈 공격을 막는 용도이다

trusted 설정을 빠뜨리면 정상 서버의 응답까지 버려져서 모든 단말이 주소를 받지 못한다. 설정 후 가장 먼저 확인할 부분이다.

## 바인딩 테이블

![DHCP 4단계 중 ACK를 보고 스위치가 MAC 주소, IP 주소, 임대 시간, VLAN, 포트를 기록한 바인딩 테이블]({{ '/assets/img/ccna/day37-binding.svg' | relative_url }})

DHCP Snooping을 켜면 스위치는 지나가는 DHCP 교환을 보고 바인딩 테이블을 만든다. 어느 포트에 어느 MAC 주소와 IP 주소가 배정되었는지 기록한 표이다. 임대 시간이 끝나면 항목이 지워진다.

```
SW1# show ip dhcp snooping
SW1# show ip dhcp snooping binding
```

- `show ip dhcp snooping`: 켜진 VLAN, trusted 포트, 속도 제한을 본다
- `show ip dhcp snooping binding`: 바인딩 테이블을 본다

고정 IP를 쓰는 호스트는 DHCP를 거치지 않으므로 표에 자동으로 생기지 않는다. 이 호스트들은 수동으로 항목을 넣거나 DAI에서 따로 허용해야 한다.

## DAI

DAI(Dynamic ARP Inspection)는 스위치를 지나가는 ARP 패킷을 검사한다. 기준은 DHCP Snooping의 바인딩 테이블이다. ARP 패킷의 송신 IP와 MAC 주소가 그 포트의 바인딩 항목과 맞지 않으면 버린다.

![공격자가 보낸 거짓 ARP 응답을 DAI가 바인딩 테이블과 비교해 IP 불일치로 버리는 과정]({{ '/assets/img/ccna/day37-dai.svg' | relative_url }})

- 기본값은 모두 untrusted이고, untrusted 포트의 ARP만 검사한다
- trusted 포트로 들어온 ARP는 검사 없이 통과한다. 다른 스위치나 라우터로 향하는 업링크에 지정한다
- DAI는 바인딩 테이블이 있어야 동작하므로 DHCP Snooping을 먼저 설정한다
- untrusted 포트에서 ARP 패킷이 초당 15개를 넘으면 기본적으로 포트를 err-disabled로 만든다

```
SW1(config)# ip arp inspection vlan 10
SW1(config)# interface gigabitethernet 0/1
SW1(config-if)# ip arp inspection trust
SW1(config-if)# exit
SW1(config)# ip arp inspection validate src-mac dst-mac ip
```

- `ip arp inspection vlan 10`: 검사할 VLAN을 정한다
- `ip arp inspection trust`: 포트를 trusted로 바꾼다
- `ip arp inspection validate`: ARP 안의 MAC 주소와 IP 주소가 올바른 형식인지 추가로 확인한다. `src-mac`은 이더넷 출발지 MAC과 ARP 안의 송신 MAC이 같은지, `dst-mac`은 목적지, `ip`는 0.0.0.0이나 멀티캐스트 같은 비정상 주소가 없는지 본다

```
SW1# show ip arp inspection
SW1# show ip arp inspection interfaces
```

고정 IP 호스트의 ARP는 바인딩 테이블에 없어서 버려진다. 이럴 때는 ARP ACL로 허용한다.

```
SW1(config)# arp access-list STATIC-HOSTS
SW1(config-arp-nacl)# permit ip host 192.168.10.5 mac host 0011.2233.8899
SW1(config-arp-nacl)# exit
SW1(config)# ip arp inspection filter STATIC-HOSTS vlan 10
```

## 정리

- DHCP Snooping은 가짜 DHCP 서버를 막고 바인딩 테이블을 만든다
- DAI는 그 표를 근거로 가짜 ARP를 막는다
- 둘 다 기본은 untrusted이다. 정상 서버, 다른 스위치, 라우터로 향하는 포트만 trusted로 지정한다
- 적용은 VLAN 단위이다

## 확인 문제

1. DHCP Snooping에서 포트의 기본 상태는 trusted와 untrusted 중 무엇인가?
2. untrusted 포트로 들어왔을 때 버려지는 DHCP 메시지를 쓰시오.
3. DHCP Snooping이 만드는 바인딩 테이블에는 어떤 정보가 기록되는가? 세 가지 이상 쓰시오.
4. DAI가 ARP 패킷을 검사할 때 기준으로 삼는 것은 무엇인가?
5. 라우터로 향하는 업링크 포트는 DAI에서 trusted와 untrusted 중 어느 쪽으로 지정하는가?

<details>
<summary>정답 보기</summary>

1. untrusted이다.
2. DHCP 서버가 보내는 메시지인 OFFER, ACK, NAK이다.
3. 클라이언트의 MAC 주소, IP 주소, VLAN, 연결된 포트, 임대 시간 가운데 세 가지이다.
4. DHCP Snooping 바인딩 테이블이다. 고정 IP 호스트는 ARP ACL로 따로 허용한다.
5. trusted이다. trusted 포트로 들어온 ARP는 검사하지 않는다.
