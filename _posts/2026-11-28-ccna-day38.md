라우터와 스위치는 설정을 바꿀 수 있는 장비라서, 장비에 로그인하는 경로가 뚫리면 네트워크 전체가 뚫린다. 오늘은 접속 경로를 암호화하고(SSH), 저장된 비밀번호를 보호하고, 로그인 관리를 서버에 맡기는(AAA) 방법을 본다.

## Telnet과 SSH

원격에서 장비의 CLI에 들어가는 방법은 Telnet과 SSH 두 가지이다.

![Telnet은 계정과 비밀번호가 평문으로 지나가 도청자가 읽을 수 있고, SSH는 암호화되어 읽을 수 없는 구성]({{ '/assets/img/ccna/day38-telnet-ssh.svg' | relative_url }})

- Telnet: TCP 23. 계정, 비밀번호, 명령이 모두 평문으로 흐른다
- SSH: TCP 22. 세션 전체가 암호화된다. 현재는 SSH 버전 2를 쓴다

실무와 시험 모두 원격 접속은 SSH만 허용하는 것이 기본이다.

![클라이언트가 TCP 22로 연결하고 버전 협상, 키 교환, 사용자 인증 순서로 SSH 세션이 시작되는 과정]({{ '/assets/img/ccna/day38-ssh-session.svg' | relative_url }})

사용자 인증보다 키 교환이 먼저이다. 비밀번호도 암호화된 채널 안에서 전달되므로 도청으로는 알 수 없다.

## 접속 경로

- 콘솔(console): 장비에 케이블로 직접 연결한다. 물리적으로 접근해야 하므로 원격 공격에는 안전하지만, 설정이 없으면 누구나 쓸 수 있다
- VTY: Telnet이나 SSH로 들어오는 가상 터미널 회선이다. 보통 `line vty 0 15`로 16개를 한 번에 설정한다
- AUX: 예전 모뎀용 포트이다. 요즘은 쓰지 않는다

## 비밀번호 보호

```
R1(config)# enable secret Str0ngEnable
R1(config)# line console 0
R1(config-line)# password ConsolePass
R1(config-line)# login
R1(config-line)# exec-timeout 5 0
R1(config-line)# exit
R1(config)# service password-encryption
```

- `enable password`: 특권 모드(enable) 비밀번호를 평문으로 저장한다. 쓰지 않는다
- `enable secret`: 같은 용도이지만 해시로 저장한다. 둘 다 있으면 secret이 우선한다
- `service password-encryption`: 콘솔, VTY 등에 평문으로 저장된 비밀번호를 type 7로 가린다. type 7은 쉽게 되돌릴 수 있어서 보호라기보다 어깨너머로 보는 것을 막는 정도이다. `enable secret`의 해시는 이 명령과 상관없다
- `exec-timeout 5 0`: 입력이 5분 0초 없으면 세션을 끊는다. 자리를 비운 사이에 콘솔이 악용되는 것을 막는다

## SSH 설정

SSH를 켜려면 호스트 이름과 도메인 이름이 있어야 키를 만들 수 있다. 호스트 이름이 기본값(Router, Switch)이면 키 생성이 거부된다.

```
R1(config)# hostname R1
R1(config)# ip domain-name example.local
R1(config)# crypto key generate rsa modulus 2048
R1(config)# ip ssh version 2
R1(config)# username admin secret Str0ngAdmin
R1(config)# line vty 0 15
R1(config-line)# transport input ssh
R1(config-line)# login local
R1(config-line)# exec-timeout 10 0
```

- `crypto key generate rsa modulus 2048`: RSA 키 쌍을 만든다. SSH 버전 2를 쓰려면 768비트 이상이 필요하고, 2048비트를 권장한다
- `ip ssh version 2`: 버전 2만 허용한다
- `username admin secret ...`: 로컬 계정을 만든다. secret이면 비밀번호가 해시로 저장된다
- `transport input ssh`: VTY에서 SSH만 받는다. Telnet은 거부된다
- `login local`: 로그인할 때 로컬 계정의 이름과 비밀번호를 확인한다. `login`만 쓰면 회선에 설정한 비밀번호 하나를 쓴다

접속 시도를 제한하는 설정도 있다.

```
R1(config)# login block-for 120 attempts 3 within 60
R1(config)# access-list 10 permit 192.168.1.0 0.0.0.255
R1(config)# line vty 0 15
R1(config-line)# access-class 10 in
```

- `login block-for 120 attempts 3 within 60`: 60초 안에 3번 실패하면 120초 동안 로그인을 막는다. 무차별 대입 공격을 늦춘다
- `access-class 10 in`: ACL 10에서 허용한 출발지만 VTY로 들어올 수 있게 한다. 관리용 대역에서만 접속하도록 제한할 때 쓴다

확인은 다음 명령으로 한다.

```
R1# show ip ssh
R1# show ssh
R1# show users
```

- `show ip ssh`: SSH가 켜져 있는지, 버전이 무엇인지 본다
- `show ssh`: 현재 SSH 세션을 본다
- `show users`: 지금 장비에 접속해 있는 사용자를 본다

## AAA

장비마다 로컬 계정을 만들면 직원이 바뀔 때마다 모든 장비를 고쳐야 한다. AAA는 로그인 관리를 서버 한 곳에 모으는 방식이다.

![관리자가 라우터에 로그인하면 라우터가 AAA 서버에 인증을 요청하고, 결과와 권한을 받는 흐름과 AAA 세 가지 역할]({{ '/assets/img/ccna/day38-aaa.svg' | relative_url }})

- 인증(Authentication): 누구인지 확인한다
- 인가(Authorization): 인증된 사용자가 무엇을 할 수 있는지 정한다. 쓸 수 있는 명령이나 privilege level이 해당한다
- 어카운팅(Accounting): 언제 접속해 무엇을 했는지 기록한다. 사고가 났을 때 추적하는 근거가 된다

AAA 서버와 통신하는 프로토콜은 두 가지이다.

| 항목 | RADIUS | TACACS+ |
|---|---|---|
| 표준 | 공개 표준 | Cisco 규격 |
| 전송 | UDP (인증 1812, 어카운팅 1813) | TCP 49 |
| 암호화 | 패킷 안의 비밀번호만 | 패킷 본문 전체 |
| AAA 분리 | 인증과 인가를 합쳐서 처리 | 인증, 인가, 어카운팅을 따로 처리 |
| 주로 쓰는 곳 | 무선, 802.1X, VPN 같은 사용자 접속 | 장비 관리자 로그인과 명령 단위 제어 |

장비 관리에는 명령 단위로 인가할 수 있는 TACACS+를 주로 쓴다.

```
R1(config)# aaa new-model
R1(config)# tacacs server TAC1
R1(config-server-tacacs)# address ipv4 192.168.1.50
R1(config-server-tacacs)# key SharedKey
R1(config-server-tacacs)# exit
R1(config)# aaa authentication login default group tacacs+ local
```

- `aaa new-model`: AAA 기능을 켠다. 이후 로그인 방식은 AAA 설정을 따른다
- `tacacs server TAC1`: 서버를 등록한다. `key`는 장비와 서버가 공유하는 비밀 값이다
- `group tacacs+ local`: 먼저 TACACS+ 서버에 묻고, 서버가 응답하지 않으면 로컬 계정을 쓴다

서버가 응답하지 않을 때만 local로 넘어간다. 서버가 응답해서 거부하면 로컬 계정으로 다시 시도하지 않는다. 서버 장애로 장비에서 쫓겨나는 일을 막으려고 local을 마지막에 넣어 둔다.

## 일본어 IT 용어

SSH는 일본어에서도 「SSH」 그대로 쓰고, 원격 접속은 「リモートアクセス」라고 한다. 인증은 「<ruby>認証<rt>にんしょう</rt></ruby>」, 인가는 「<ruby>認可<rt>にんか</rt></ruby>」, 평문은 「<ruby>平文<rt>ひらぶん</rt></ruby>」, 공개키는 「<ruby>公開鍵<rt>こうかいかぎ</rt></ruby>」이다. 어카운팅은 「アカウンティング」, 비밀번호는 「パスワード」라고 한다. 오늘 일본어 단어 글에는 원격, 평문, 권한, 방치 같은 말이 나온다.
