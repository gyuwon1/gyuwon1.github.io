스위치 포트에 아무 장비나 꽂아도 통신이 되는 것이 기본 상태이다. 포트 시큐리티는 포트마다 접속을 허용할 MAC 주소와 개수를 제한해서, 허가되지 않은 장비와 MAC 플러딩 같은 공격을 막는다.

## 동작 원리

![허용 목록에 있는 MAC의 프레임은 통과하고, 최대 개수를 넘는 새 MAC의 프레임은 위반으로 처리되는 모습]({{ '/assets/img/ccna/day34-concept.svg' | relative_url }})

스위치는 포트로 들어온 프레임의 출발지 MAC 주소를 보안 MAC 테이블에 등록한다. 등록된 개수가 설정한 최대 개수에 차 있는데 새 MAC에서 프레임이 오면 위반으로 본다. 등록된 MAC이 다른 보안 포트에서 같은 VLAN으로 들어오는 경우도 위반이다.

- 기본 상태에서는 포트 시큐리티가 꺼져 있다
- 켜면 최대 MAC 수의 기본값은 1, 위반 모드의 기본값은 shutdown이다
- 포트가 `switchport mode access`나 `switchport mode trunk`로 고정되어 있어야 켤 수 있다. 협상으로 모드가 정해지는 dynamic 포트에는 적용되지 않는다
- 포트마다 허용 개수를 정해 두므로, 한 포트에 MAC 주소를 대량으로 쏟아붓는 MAC 플러딩 공격도 개수 제한에서 막힌다

## 보안 MAC 주소의 종류

![정적, 동적, 스티키 보안 MAC 주소가 만들어지는 방법, 저장되는 곳, 재부팅 후 상태를 비교한 표]({{ '/assets/img/ccna/day34-mactypes.svg' | relative_url }})

- 정적: `switchport port-security mac-address` 명령으로 직접 입력한다
- 동적: 따로 설정하지 않으면 프레임을 받으며 자동으로 배운다. 재부팅하면 사라진다
- 스티키: `switchport port-security mac-address sticky`를 켜면 배운 MAC이 running-config에 정적 항목처럼 추가된다. 재부팅 후에도 남기려면 `copy running-config startup-config`로 저장해야 한다

스티키는 모든 MAC을 일일이 입력하지 않아도 되어서 현장에서 많이 쓴다. 처음 연결된 장비의 MAC이 자동으로 등록된다.

## violation 모드

![protect, restrict, shutdown 모드가 위반 프레임, 로그, 카운터, 포트 상태, 기존 장비 통신에서 어떻게 다른지 비교한 표]({{ '/assets/img/ccna/day34-violation.svg' | relative_url }})

- protect: 위반 프레임만 버린다. 로그도 남기지 않고 위반 카운터도 올리지 않는다
- restrict: 위반 프레임을 버리고, 로그와 SNMP 트랩을 남기며 카운터를 올린다
- shutdown: 포트를 err-disabled 상태로 만들어 포트 전체를 끈다. 로그를 남기고 카운터를 올린다

shutdown 모드에서는 포트가 꺼지므로 정상 장비의 통신도 함께 끊긴다. 대신 위반을 바로 알아차릴 수 있다.

## 설정

```
Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 2
Switch(config-if)# switchport port-security mac-address sticky
Switch(config-if)# switchport port-security violation shutdown
```

`switchport port-security` 한 줄만 입력해도 기본값(최대 1, shutdown)으로 켜진다. 나머지 줄은 기본값을 바꿀 때만 넣는다. IP 전화기 뒤에 PC를 연결하는 포트는 MAC이 둘 이상 보일 수 있으므로 최대 개수를 그에 맞게 늘려야 하는 경우가 있다.

미사용 포트는 인터페이스에서 `shutdown`으로 꺼 두는 방법이 기본이다.

## 확인


`Port Status`가 Secure-up이면 정상이다. 위반이 일어나면 Secure-shutdown으로 바뀌고, `Last Source Address:Vlan`에 위반을 일으킨 MAC과 VLAN이 표시된다. 등록된 MAC 목록은 `show port-security address`로 본다.

## err-disabled 복구

shutdown 모드에서 위반이 일어나면 다음과 같은 로그가 나온다.

```
%PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by MAC address aaaa.bbbb.0066 on port GigabitEthernet0/1.
%PM-4-ERR_DISABLE: psecure-violation error detected on Gi0/1, putting Gi0/1 in err-disable state
```

위반 장비를 먼저 분리한 뒤 포트를 껐다 켠다.

```
Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# shutdown
Switch(config-if)# no shutdown
```

장비를 분리하지 않고 포트만 켜면 다시 위반이 생겨 err-disabled로 돌아간다. 자동 복구를 쓰고 싶으면 `errdisable recovery cause psecure-violation`을 설정한다. 복구 간격은 `errdisable recovery interval`로 바꾸며 기본값은 300초이다.

## 확인 문제

1. 포트 시큐리티를 켰을 때 최대 MAC 수와 위반 모드의 기본값은 무엇인가?
2. 위반 프레임만 버리고 로그도 카운터도 남기지 않는 모드는 무엇인가?
3. 스티키 보안 MAC 주소는 동적 보안 MAC 주소와 무엇이 다른가?
4. shutdown 모드로 err-disabled가 된 포트를 복구하는 명령 순서를 쓰시오.
5. dynamic desirable로 협상 중인 포트에서 포트 시큐리티를 켤 수 있는가?
