ACL(Access Control List)은 패킷의 주소 같은 조건을 위에서부터 차례로 비교해서 통과시킬지 버릴지 정하는 규칙 목록이다. 표준 ACL은 패킷의 출발지 IP 주소만 본다.

## 평가 순서

![패킷의 출발지 주소를 ACL 첫 줄부터 비교하고, 일치하면 처리하고 끝내며, 끝까지 일치하지 않으면 암묵적 deny any에 걸려 버려지는 흐름]({{ '/assets/img/ccna/day35-flow.svg' | relative_url }})

- 첫 줄부터 아래로 비교하다가 처음 일치한 줄의 permit 또는 deny를 적용하고, 이후 줄은 보지 않는다
- 어느 줄에도 일치하지 않으면 마지막에 보이지 않는 `deny any`가 적용되어 버려진다. 이를 암묵적 거부라고 한다
- 그래서 줄 순서가 결과를 바꾼다. 범위가 좁은 조건을 위에, 넓은 조건을 아래에 둔다
- permit 줄이 하나도 없는 ACL은 모든 패킷을 버린다

## 번호와 이름

- 번호 ACL: 표준은 1~99, 1300~1999 범위의 번호를 쓴다 (확장은 100~199, 2000~2699)
- 이름 ACL: `ip access-list standard 이름`으로 만든다. `standard` 또는 `extended` 키워드로 종류를 지정한다

## 와일드카드 마스크

![와일드카드 마스크에서 0 비트는 일치해야 하고 1 비트는 무시되는 것을 0.0.0.255와 0.0.0.15 두 예로 비교한 그림]({{ '/assets/img/ccna/day35-wildcard.svg' | relative_url }})

ACL은 서브넷 마스크가 아니라 와일드카드 마스크로 범위를 정한다. 0인 비트는 주소와 일치해야 하고, 1인 비트는 무시한다. 서브넷 마스크와 0과 1의 의미가 반대이다.

- 서브넷 마스크 255.255.255.0에 해당하는 와일드카드는 0.0.0.255이다. 각 옥텟을 255에서 뺀 값이다
- 한 대의 호스트는 `host 192.168.1.10`으로 쓴다. `192.168.1.10 0.0.0.0`과 같다
- 모든 주소는 `any`로 쓴다. `0.0.0.0 255.255.255.255`와 같다
- 와일드카드 마스크는 0과 1이 꼭 연속되지 않아도 되지만, 시험과 현장에서는 대부분 연속된 형태를 쓴다

## 설정

번호 ACL이다.

```
R2(config)# access-list 10 permit 192.168.1.0 0.0.0.255
R2(config)# access-list 10 deny host 192.168.2.10
R2(config)# access-list 10 permit any
```

이름 ACL로 같은 내용을 만들면 다음과 같다. 줄마다 시퀀스 번호가 붙는다.

```
R2(config)# ip access-list standard SERVER-IN
R2(config-std-nacl)# 10 permit 192.168.1.0 0.0.0.255
R2(config-std-nacl)# 20 deny host 192.168.2.10
R2(config-std-nacl)# 30 permit any
```

이름 ACL은 `no 20`처럼 시퀀스 번호로 특정 줄만 지울 수 있고, 원하는 시퀀스 번호를 지정하면 중간에 새 줄을 끼워 넣을 수 있다. 번호 ACL도 최신 IOS에서는 `ip access-list standard 10`으로 들어가면 같은 방식으로 편집할 수 있다. 줄을 새로 추가하면 기본적으로 맨 아래에 붙는다. 설명이 필요하면 `remark 문구`를 쓴다.

ACL은 만들기만 해서는 동작하지 않고, 인터페이스에 적용해야 한다.

```
R2(config)# interface gigabitethernet 0/1
R2(config-if)# ip access-group 10 out
```

방향은 `in`(라우터로 들어오는 패킷)과 `out`(라우터에서 나가는 패킷)이다. 한 인터페이스에 방향마다 ACL 하나만 적용할 수 있다. 위 예의 `192.168.2.10`은 2번 줄에서 걸러진다. 같은 대역의 다른 PC는 `192.168.2.0` 대역이 permit되지 않았으므로 3번 줄의 `permit any`로 통과한다. 이를 막으려면 `deny 192.168.2.0 0.0.0.255`로 바꾼다.

## 적용 위치

![PC1과 PC2가 R1, R2를 거쳐 서버 네트워크와 다른 네트워크로 가는 구성에서, R2의 서버 쪽 인터페이스 outbound에 표준 ACL을 적용한 그림]({{ '/assets/img/ccna/day35-placement.svg' | relative_url }})

표준 ACL은 목적지를 구분하지 못한다. 출발지에 가깝게 걸면 그 출발지가 가는 모든 목적지가 막힌다. 그래서 목적지에 가까운 곳에 적용하는 것이 원칙이다. 확장 ACL은 반대로 출발지에 가깝게 적용한다. 이 내용은 다음 글에서 다룬다.

## 확인

```
R2# show access-lists
Standard IP access list 10
    10 permit 192.168.1.0, wildcard bits 0.0.0.255 (12 matches)
    20 deny   192.168.2.10 (4 matches)
    30 permit any (30 matches)
```

```
R2# show ip interface gigabitethernet 0/1
...
  Outgoing access list is 10
  Inbound  access list is not set
...
```

`show access-lists`의 matches는 그 줄에 일치한 패킷 수이다. 어느 줄이 쓰이고 있는지 볼 수 있다. 인터페이스에 어떤 ACL이 어느 방향으로 걸렸는지는 `show ip interface`나 `show running-config`로 확인한다. 카운터는 `clear access-list counters`로 초기화한다.

## 주의할 점

- 암묵적 `deny any` 때문에 일부만 막으려 해도 마지막 줄에 `permit any`를 넣어야 나머지가 통과한다
- 인터페이스에 적용한 ACL을 전부 지우면 암묵적 거부가 사라져 다시 모두 통과한다. 반대로 줄이 하나라도 있는 ACL을 적용하면 일치하지 않는 나머지는 전부 막힌다
- 원격 접속을 쓰고 있는 라우터에서 접속 경로를 막는 ACL을 적용하지 않도록 조심한다
- 라우터가 직접 만든 패킷(라우팅 프로토콜 업데이트 등)에는 outbound ACL이 적용되지 않는다
- 표준 ACL은 VTY 회선에도 `access-class`로 걸 수 있다. 장비 접근 제한은 Day 38에서 다룬다

## 일본어 IT 용어

ACL은 「アクセスコントロールリスト」 또는 「アクセスリスト」라고 한다. 와일드카드 마스크는 「ワイルドカードマスク」, 허용은 「<ruby>許可<rt>きょか</rt></ruby>」(permit), 거부는 「<ruby>拒否<rt>きょひ</rt></ruby>」(deny)이다. 암묵적 거부는 「<ruby>暗黙<rt>あんもく</rt></ruby>の<ruby>拒否<rt>きょひ</rt></ruby>」라고 쓴다. 오늘 일본어 단어 글에는 합치, 통과시키다, 번호 같은 말이 나온다.

## 확인 문제

1. 표준 ACL이 패킷에서 확인하는 항목은 무엇인가?
2. ACL의 마지막에 보이지 않게 존재하는 줄은 무엇이며 어떤 동작을 하는가?
3. 서브넷 마스크 255.255.255.240에 해당하는 와일드카드 마스크를 쓰시오.
4. 표준 ACL은 출발지와 목적지 중 어디에 가깝게 적용하는 것이 원칙인가? 이유도 쓰시오.
5. 번호 ACL 10을 GigabitEthernet 0/1의 나가는 방향에 적용하는 명령을 쓰시오.
