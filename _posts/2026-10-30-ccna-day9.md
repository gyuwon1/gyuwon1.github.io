IPv4 주소는 32비트라서 약 43억 개뿐이고, 사설 주소와 NAT로 버텨 왔다. IPv6는 주소를 128비트로 늘려 이 문제를 근본적으로 없앴다. 오늘은 표기법과 주소 종류를 본다.

## 주소 표기법

IPv6 주소는 128비트를 16비트씩 8그룹으로 나눠 16진수로 쓰고, 그룹은 콜론(:)으로 구분한다. 완전한 표기는 길어서 두 가지 규칙으로 줄인다.

1. 각 그룹 앞쪽의 0은 지운다. 0000은 0 하나로 쓴다.
2. 연속된 0 그룹은 ::로 바꾼다. 이 규칙은 주소 하나에서 한 번만 쓸 수 있다.

![IPv6 주소를 두 단계로 줄이는 과정]({{ '/assets/img/ccna/day9-notation.svg' | relative_url }})

::를 두 번 쓰면 각각에 0 그룹이 몇 개씩 들어가는지 알 수 없다. 그래서 한 번만 허용한다. 0 그룹이 여러 곳에 있으면 보통 가장 긴 구간을 ::로 줄인다.

되돌릴 때는 보이는 그룹 수를 세고, 8에서 뺀 만큼 0 그룹을 :: 자리에 채운다. 앞의 0도 4자리가 되도록 채운다. 16진수는 대소문자를 구분하지 않는다.

| 줄인 표기 | 전체 표기 |
|-----------|-----------|
| 2001:db8::1 | 2001:0db8:0000:0000:0000:0000:0000:0001 |
| FE80::1 | FE80:0000:0000:0000:0000:0000:0000:0001 |
| :: | 0000:0000:0000:0000:0000:0000:0000:0000 |

## 프리픽스 길이

IPv4의 CIDR처럼 IPv6도 `주소/프리픽스 길이`로 쓴다. 앞쪽 몇 비트가 네트워크 부분인지 나타낸다. 서브넷 하나에는 보통 /64를 쓴다. 앞 64비트가 네트워크 프리픽스이고 뒤 64비트는 인터페이스 ID다.

![IPv6 주소의 프리픽스와 인터페이스 ID 구조]({{ '/assets/img/ccna/day9-structure.svg' | relative_url }})

ISP가 사이트에 /48을 주면 그 안에서 서브넷 ID 16비트로 서브넷 65,536개를 만든다. IPv4처럼 호스트 수에 맞춰 마스크를 아끼는 VLSM 계산은 필요 없다. 문서 예제에는 2001:db8::/32가 쓰인다. 이 프리픽스는 설명용으로 예약되어 있어 실제 인터넷에서 쓰이지 않는다.

## 주소 종류

![IPv6 주소 종류와 프리픽스]({{ '/assets/img/ccna/day9-types.svg' | relative_url }})

- 글로벌 유니캐스트: 인터넷에서 라우팅되는 공인 주소다. 현재 할당은 2000::/3 범위에서 이뤄진다.
- 유니크 로컬: FC00::/7 범위이고 실제로는 FD로 시작하는 주소를 쓴다. IPv4의 사설 주소와 비슷하게 조직 내부용이다.
- 링크 로컬: FE80::/10 범위다. 같은 링크 안에서만 유효하고 라우터가 넘기지 않는다. IPv6가 켜진 인터페이스에는 자동으로 생기며, 이웃 탐색이나 라우팅 프로토콜의 다음 홉 주소로 쓰인다.
- 멀티캐스트: FF00::/8 범위다. FF02::1은 링크의 모든 노드, FF02::2는 링크의 모든 라우터를 가리킨다.
- 루프백은 ::1, 미지정 주소는 ::이다. 미지정 주소는 아직 주소를 받지 못한 호스트가 출발지로 쓴다.

IPv6에는 브로드캐스트가 없다. IPv4에서 브로드캐스트로 하던 일은 멀티캐스트가 맡고, ARP는 NDP(Neighbor Discovery Protocol)로 바뀌었다. 같은 주소를 여러 장비에 두고 가장 가까운 장비가 받게 하는 애니캐스트는 유니캐스트 주소 공간을 그대로 쓴다.

## 인터페이스 ID와 EUI-64

인터페이스 ID는 직접 정하거나 MAC 주소로 만든다. EUI-64 방식은 48비트 MAC 주소를 가운데에서 둘로 나누고 FFFE를 끼운 뒤, 첫 바이트의 7번째 비트(U/L 비트)를 반전시킨다.

MAC 주소가 00:1A:2B:3C:4D:5E라면 다음과 같다.

1. 가운데에 FFFE를 넣는다: 00:1A:2B:FF:FE:3C:4D:5E
2. 첫 바이트 00의 7번째 비트를 뒤집어 02로 바꾼다: 02:1A:2B:FF:FE:3C:4D:5E
3. 인터페이스 ID는 021A:2BFF:FE3C:4D5E가 된다.

## 설정 예시

```
Router(config)# ipv6 unicast-routing
Router(config)# interface GigabitEthernet0/0
Router(config-if)# ipv6 address 2001:db8:1:1::1/64
Router(config-if)# no shutdown

Router(config)# interface GigabitEthernet0/1
Router(config-if)# ipv6 address 2001:db8:1:2::/64 eui-64
Router(config-if)# ipv6 address fe80::1 link-local

Router# show ipv6 interface brief
```

`ipv6 unicast-routing`은 라우터가 IPv6 패킷을 전달하게 하는 명령이다. 이 명령이 없으면 주소만 설정되고 라우팅은 되지 않는다. `eui-64`를 붙이면 프리픽스만 적어도 인터페이스 ID가 MAC 주소로 자동 계산된다. 링크 로컬 주소는 `link-local`을 붙여 직접 지정할 수 있다.

## 일본어 용어

IPv6 주소는 「IPv6アドレス」, 프리픽스 길이는 「プレフィックス<ruby>長<rt>ちょう</rt></ruby>」라고 한다. 주소를 줄여 쓰는 것은 「<ruby>省略<rt>しょうりゃく</rt></ruby>」, 표기 방식은 「<ruby>表記<rt>ひょうき</rt></ruby>」다. 둘 다 오늘 일본어 단어 글에 나온다.

## 확인 문제

1. FE80:0000:0000:0000:0202:B3FF:FE1E:8329를 가장 짧게 줄여 쓰면?
2. 2001:db8:a::1을 전체 표기로 풀어 쓰면?
3. 한 주소에 ::를 두 번 쓸 수 없는 이유는?
4. FE80으로 시작하는 주소는 어떤 종류이고 어디까지 전달되는가?
5. MAC 주소 00:1A:2B:3C:4D:5E로 만든 EUI-64 인터페이스 ID는?

<details>
<summary>정답 보기</summary>

1. FE80::202:B3FF:FE1E:8329다. 연속된 0 그룹 세 개를 ::로 줄이고 0202의 앞 0을 지운다.
2. 2001:0db8:000a:0000:0000:0000:0000:0001이다. 보이는 그룹이 4개이므로 :: 자리에 0 그룹 4개가 들어간다.
3. ::가 두 번이면 각각에 0 그룹이 몇 개씩 들어가는지 정할 수 없어 주소를 하나로 복원할 수 없기 때문이다.
4. 링크 로컬 주소다. 같은 링크 안에서만 유효하고 라우터가 다른 네트워크로 전달하지 않는다.
5. 021A:2BFF:FE3C:4D5E다. 가운데에 FFFE를 넣고 첫 바이트 00의 7번째 비트를 뒤집어 02로 바꾼다.
