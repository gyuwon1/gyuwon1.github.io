4계층(전송 계층)은 데이터를 어느 애플리케이션에 전달할지 정하고, 얼마나 신뢰성 있게 보낼지 정한다. 대표 프로토콜이 TCP와 UDP다.

## TCP와 UDP

| 항목 | TCP | UDP |
|------|-----|-----|
| 연결 | 연결 지향 (먼저 연결을 맺는다) | 비연결 |
| 신뢰성 | 순서 보장, 재전송, 확인 응답 | 보장하지 않음 |
| 흐름 제어 | 윈도우 크기로 조절 | 없음 |
| 헤더 | 최소 20바이트 | 8바이트 |
| 속도 | 상대적으로 느림 | 빠름 |
| 사용 예 | 웹(HTTP/HTTPS), 메일, SSH, FTP | DNS, DHCP, VoIP, 스트리밍 |

TCP는 등기 우편처럼 받았다는 확인을 받고 못 받았으면 다시 보낸다. UDP는 일반 엽서처럼 보내기만 하고 도착 여부를 확인하지 않는다. 음성 통화처럼 조금 빠져도 지연이 더 문제인 서비스는 UDP를 쓴다.

![TCP와 UDP 헤더 비교]({{ '/assets/img/ccna/day4-tcp-udp-header.svg' | relative_url }})

TCP 헤더에는 순서 번호와 확인 응답 번호, 플래그, 윈도우 크기가 있다. 이 필드들이 순서 보장, 재전송, 흐름 제어를 가능하게 한다. UDP 헤더에는 포트 두 개, 길이, 체크섬만 있다.

## 포트 번호

IP 주소는 호스트를 찾고, 포트 번호는 그 호스트 안의 애플리케이션을 찾는다. 포트는 16비트라서 0~65535의 값이다.

| 범위 | 이름 | 설명 |
|------|------|------|
| 0~1023 | 잘 알려진 포트 | 표준 서비스가 사용 |
| 1024~49151 | 등록된 포트 | 특정 애플리케이션이 등록해 사용 |
| 49152~65535 | 동적(임시) 포트 | 클라이언트가 접속할 때 임의로 사용 |

시험에 자주 나오는 포트는 아래와 같다.

| 포트 | 프로토콜 | 서비스 |
|------|----------|--------|
| 20, 21 | TCP | FTP (데이터, 제어) |
| 22 | TCP | SSH |
| 23 | TCP | Telnet |
| 25 | TCP | SMTP |
| 53 | UDP, TCP | DNS |
| 67, 68 | UDP | DHCP (서버, 클라이언트) |
| 69 | UDP | TFTP |
| 80 | TCP | HTTP |
| 110 | TCP | POP3 |
| 123 | UDP | NTP |
| 161, 162 | UDP | SNMP |
| 443 | TCP | HTTPS |

![포트 번호와 소켓]({{ '/assets/img/ccna/day4-ports.svg' | relative_url }})

클라이언트는 목적지 포트로 서비스 포트(80 등)를 쓰고, 출발지 포트는 동적 포트 중에서 하나를 고른다. 같은 PC에서 브라우저 탭을 여러 개 열어도 출발지 포트가 달라서 응답이 섞이지 않는다. IP 주소와 포트 번호를 합친 것을 소켓이라고 부른다.

## 3-way handshake

TCP는 데이터를 보내기 전에 세그먼트 세 개를 주고받아 연결을 맺는다.

![TCP 3-way handshake]({{ '/assets/img/ccna/day4-handshake.svg' | relative_url }})

1. 클라이언트가 SYN을 보낸다. 자신의 초기 순서 번호를 담는다.
2. 서버가 SYN+ACK로 답한다. 클라이언트의 번호에 1을 더한 값을 확인 응답 번호로 넣고, 자신의 초기 순서 번호도 보낸다.
3. 클라이언트가 ACK를 보낸다. 서버의 번호에 1을 더한 값을 확인 응답 번호로 넣는다.

이후 양쪽이 ESTABLISHED 상태가 되어 데이터를 주고받는다. 연결을 끝낼 때는 FIN과 ACK를 양방향으로 주고받는 4-way 종료를 쓰고, 비정상 상황에서는 RST로 연결을 바로 끊는다.

## 순서 번호와 윈도우

TCP는 보낸 바이트에 번호를 붙인다. 수신 쪽은 받은 데이터 다음에 기대하는 번호를 ACK로 알려 준다. ACK가 오지 않으면 송신 쪽이 같은 데이터를 다시 보낸다. 윈도우 크기는 수신 쪽이 ACK를 기다리지 않고 한 번에 받을 수 있는 양이다. 수신 쪽 처리가 밀리면 윈도우를 줄여 송신 속도를 늦추게 하며, 이것이 흐름 제어다.

## 확인 명령

호스트에서 현재 연결과 열린 포트를 볼 때 쓴다. Windows와 Linux 모두 아래 형식이 통한다.

```
netstat -an
```

출력의 State 열에 LISTEN(대기), ESTABLISHED(연결됨), TIME_WAIT 등이 보인다.

## 확인 문제

1. TCP와 UDP 중 연결을 먼저 맺고 순서를 보장하는 쪽은?
2. HTTPS, SSH, DNS가 쓰는 기본 포트 번호는?
3. 3-way handshake에서 세그먼트 세 개의 순서는?
4. 클라이언트가 접속할 때 출발지 포트로 쓰는 범위는?
5. DNS 조회나 음성 통화에 UDP를 주로 쓰는 이유는?

<details>
<summary>정답 보기</summary>

1. TCP
2. HTTPS는 TCP 443, SSH는 TCP 22, DNS는 UDP 53(대용량 응답은 TCP 53)
3. SYN, SYN+ACK, ACK
4. 동적(임시) 포트인 49152~65535 범위 (OS에 따라 다른 범위를 쓰기도 한다)
5. 헤더가 작고 연결 설정이 없어서 빠르고, 일부 손실보다 지연이 더 문제인 경우가 많기 때문이다.
