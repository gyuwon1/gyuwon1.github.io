Day 13에서 VLAN을 나눴지만 스위치가 두 대 이상이면 같은 VLAN이 스위치 사이로 이어져야 한다. 스위치 사이의 링크 하나로 여러 VLAN의 프레임을 함께 나르는 것이 트렁크다.

## 트렁크가 필요한 이유

VLAN마다 스위치 사이에 케이블을 하나씩 연결하면 VLAN 수만큼 포트와 케이블이 든다. 트렁크 링크를 쓰면 링크 하나로 모든 VLAN의 프레임이 지나간다.

![SW1과 SW2 사이의 트렁크 링크 하나로 VLAN 10과 VLAN 20 프레임이 함께 전달되고 PC는 액세스 포트에 연결된 구성]({{ '/assets/img/ccna/day14-trunk-link.svg' | relative_url }})

문제는 받는 스위치가 프레임이 어느 VLAN 것인지 알아야 한다는 점이다. 이더넷 프레임에는 VLAN 정보가 없으므로, 트렁크에서는 프레임에 VLAN 번호를 적은 태그를 붙인다. 이 방식의 표준이 IEEE 802.1Q다.

## 802.1Q 태그

802.1Q는 출발지 MAC 주소 뒤에 4바이트 태그를 끼워 넣는다.

![일반 이더넷 프레임과 802.1Q 태그가 삽입된 프레임을 비교하고 태그의 TPID, PCP, DEI, VLAN ID 필드를 나타낸 그림]({{ '/assets/img/ccna/day14-8021q-frame.svg' | relative_url }})

| 필드 | 크기 | 내용 |
|------|------|------|
| TPID | 16비트 | 항상 0x8100. 이 프레임에 태그가 있다는 표시 |
| PCP | 3비트 | 우선순위. QoS에서 쓴다 |
| DEI | 1비트 | 혼잡할 때 버려도 되는 프레임인지 표시 |
| VLAN ID | 12비트 | VLAN 번호 (1~4094) |

- 태그가 붙으면 프레임이 4바이트 늘어 최대 1518바이트에서 1522바이트가 된다
- 프레임 내용이 바뀌므로 FCS는 다시 계산한다
- 태그는 트렁크 포트에서 나갈 때 붙이고, 반대편 스위치가 받아 액세스 포트로 내보낼 때 뗀다. PC는 태그를 보지 못한다

## 네이티브 VLAN

트렁크에서 딱 하나의 VLAN은 태그 없이 전달할 수 있다. 이를 네이티브 VLAN이라 하고 기본값은 VLAN 1이다. 태그 없는 프레임을 받은 스위치는 그 프레임을 네이티브 VLAN 소속으로 처리한다.

![트렁크에서 VLAN 10과 20은 태그가 붙고 네이티브 VLAN은 태그 없이 전달되며, 양쪽 네이티브 VLAN이 다르면 프레임이 다른 VLAN으로 들어가는 그림]({{ '/assets/img/ccna/day14-native-vlan.svg' | relative_url }})

네이티브 VLAN은 양쪽 트렁크 포트에서 같아야 한다. 한쪽이 1, 반대쪽이 99이면 VLAN 1의 프레임이 반대편에서 VLAN 99로 들어간다. 이때 CDP가 네이티브 VLAN 불일치 메시지를 띄우고, 통신이 의도와 다르게 동작한다.

- 기본값 VLAN 1을 그대로 쓰면 사용자 트래픽과 관리 트래픽이 섞인다. 사용하지 않는 VLAN(예: 99)을 네이티브로 지정하는 방식이 보안상 권장된다
- 네이티브 VLAN 번호는 설정으로 바꿀 수 있고, 양쪽을 같은 값으로 맞춘다

## 설정

```
SW1(config)# interface gigabitethernet0/1
SW1(config-if)# switchport trunk encapsulation dot1q
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
SW1(config-if)# end
```

- `switchport trunk encapsulation dot1q`는 802.1Q를 지정한다. ISL도 지원하는 구형 스위치에서만 필요하고, 802.1Q만 지원하는 스위치에서는 이 명령이 없어도 되며 입력하면 오류가 난다
- `switchport mode trunk`는 포트를 트렁크로 고정한다
- `switchport trunk native vlan 99`는 네이티브 VLAN을 99로 바꾼다
- `switchport trunk allowed vlan`은 트렁크로 지나갈 VLAN을 제한한다. 기본값은 모든 VLAN이다. 목록을 통째로 바꾸므로 `add`를 쓰지 않으면 기존 목록이 대체된다

반대편 스위치에도 같은 설정을 넣는다. 네이티브 VLAN과 허용 VLAN 목록이 어긋나면 통신이 끊기거나 일부 VLAN만 통한다.

## DTP

Cisco 스위치는 DTP라는 프로토콜로 상대와 트렁크 여부를 자동 협상할 수 있다. 포트 모드는 다음과 같다.

| 모드 | 동작 |
|------|------|
| access | 트렁크가 되지 않는 액세스 포트로 고정 |
| trunk | 트렁크로 고정하고 상대에게도 트렁크 협상을 보낸다 |
| dynamic desirable | 트렁크가 되도록 적극적으로 협상 |
| dynamic auto | 상대가 요청하면 트렁크가 되고 스스로는 요청하지 않음 |

양쪽이 모두 dynamic auto이면 트렁크가 만들어지지 않는다. 협상 결과가 불확실하므로 실무에서는 양쪽을 `switchport mode trunk`로 고정하고, 협상 메시지를 끄기 위해 `switchport nonegotiate`를 함께 쓰는 경우가 많다.

## 확인 명령

```
SW1# show interfaces trunk

Port        Mode         Encapsulation  Status        Native vlan
Gi0/1       on           802.1q         trunking      99

Port        Vlans allowed on trunk
Gi0/1       10,20,99

SW1# show interfaces gi0/1 switchport
```

- `show interfaces trunk`는 트렁크 포트의 모드, 캡슐화, 네이티브 VLAN, 허용 VLAN을 보여 준다
- `show interfaces gi0/1 switchport`는 Administrative Mode와 Operational Mode를 구분해서 보여 준다. 설정은 trunk인데 실제 동작이 다르면 여기서 확인한다

## 확인 문제

1. 802.1Q 태그의 크기와 그 안에서 VLAN 번호를 담는 필드의 비트 수는?
2. 트렁크 링크에서 태그 없이 전달되는 VLAN을 무엇이라 부르며, 기본값은 몇 번인가?
3. SW1 트렁크의 네이티브 VLAN이 1이고 SW2는 99일 때 어떤 문제가 생기는가?
4. 트렁크에서 VLAN 10과 20만 지나가게 하는 명령은?
5. 양쪽 포트가 모두 dynamic auto일 때 트렁크가 만들어지는가?

<details>
<summary>정답 보기</summary>

1. 4바이트이고, VLAN ID 필드는 12비트다.
2. 네이티브 VLAN이고 기본값은 VLAN 1이다.
3. SW1이 보낸 VLAN 1의 태그 없는 프레임을 SW2가 VLAN 99로 처리해 VLAN이 섞인다. CDP에 네이티브 VLAN 불일치 메시지가 뜬다.
4. `switchport trunk allowed vlan 10,20`이다.
5. 만들어지지 않는다. 둘 다 상대의 요청을 기다리기만 해서 액세스 포트로 남는다.
</details>
