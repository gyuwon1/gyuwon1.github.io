스위치 사이에 링크를 여러 개 연결해도 STP는 고리를 막기 위해 하나만 포워딩하고 나머지를 블로킹한다. EtherChannel은 여러 물리 링크를 논리 링크 하나로 묶어 이 문제를 푼다.

## 왜 묶는가

![스위치 사이 링크 두 개 중 하나가 STP로 블로킹되는 경우와, 두 링크를 Port-channel 1로 묶어 모두 사용하는 경우 비교]({{ '/assets/img/ccna/day18-stp-vs-etherchannel.svg' | relative_url }})

묶은 링크를 Port-channel(포트 채널)이라 부른다. 효과는 세 가지다.

- 대역폭: 묶은 링크들의 대역폭을 함께 쓴다. 1Gbps 링크 두 개면 합쳐서 2Gbps이다
- 이중화: 묶음 안의 링크 하나가 끊겨도 나머지 링크로 통신이 이어진다. STP 재계산도 일어나지 않는다
- 관리: STP, 트렁크, VLAN 설정을 Port-channel 인터페이스 하나에서 한다

STP는 Port-channel을 링크 하나로 본다. 그래서 묶음 안의 포트들은 블로킹되지 않는다.

## 부하 분산

링크를 묶어도 한 프레임을 쪼개서 여러 링크로 보내지는 않는다. 프레임마다 출발지와 목적지 주소 같은 값으로 해시를 계산하고, 그 결과로 묶음 안의 포트 하나를 고른다.

![출발지와 목적지 주소로 해시를 계산해 Port-channel 안의 포트 하나를 고르는 그림]({{ '/assets/img/ccna/day18-hash.svg' | relative_url }})

같은 주소 조합의 프레임은 항상 같은 포트로 나간다. 프레임 순서가 뒤바뀌는 것을 막기 위해서다. 반대로 통신하는 쌍이 적으면 한 포트에 몰릴 수 있다. 해시에 쓸 값은 장비에 따라 MAC, IP, 포트 번호 등에서 고른다.

```
SW1(config)# port-channel load-balance src-dst-ip
SW1# show etherchannel load-balance
```

지원하는 방식과 기본값은 플랫폼마다 다르다. 묶인 링크의 대역폭을 전부 한 통신이 쓸 수 있는 것은 아니다.

## 협상 프로토콜

묶는 방법은 세 가지다.

| 방식 | 설명 | 모드 |
|------|------|------|
| LACP | IEEE 표준(802.3ad, 802.1AX). 다른 제조사 장비와도 쓴다 | active, passive |
| PAgP | Cisco 전용 | desirable, auto |
| 정적 | 협상 없이 강제로 묶는다 | on |

![LACP, PAgP, on 모드별로 양쪽 모드 조합에서 묶이는지 여부를 정리한 표]({{ '/assets/img/ccna/day18-modes.svg' | relative_url }})

active와 desirable은 먼저 협상을 시작하는 쪽이고, passive와 auto는 상대가 시작해야 응답하는 쪽이다. 그래서 양쪽 모두 passive(또는 auto)이면 서로 기다리기만 하고 묶이지 않는다. on은 협상 자체를 하지 않으므로 상대도 on이어야 하며, LACP나 PAgP와는 묶이지 않는다. 시험과 실무에서는 표준인 LACP를 쓰고 양쪽을 active로 두는 구성이 가장 흔하다.

## 묶기 전 조건

묶음 안의 포트는 설정이 같아야 한다.

- 속도와 듀플렉스가 같다
- 액세스 포트라면 같은 VLAN, 트렁크라면 같은 허용 VLAN과 네이티브 VLAN이다
- 모드(액세스 또는 트렁크)가 같다

LACP는 한 묶음에서 최대 8개 포트를 활성으로 쓴다. 장비에 따라 대기(standby) 포트를 8개까지 더 둘 수 있다.

## 설정과 확인

```
SW1(config)# interface range gigabitEthernet 0/1 - 2
SW1(config-if-range)# channel-group 1 mode active
SW1(config-if-range)# exit
SW1(config)# interface port-channel 1
SW1(config-if)# switchport mode trunk
```

`channel-group 1`을 입력하면 Port-channel 1 인터페이스가 자동으로 만들어진다. SW2에도 같은 방식으로 설정한다. 반대편은 `mode active` 또는 `mode passive`를 쓴다. PAgP를 쓰려면 `mode desirable`, 정적으로 묶으려면 `mode on`을 입력한다. 이후 트렁크나 VLAN 설정은 Port-channel 인터페이스에서 하며, 설정이 묶음 안의 물리 포트에 반영된다.

확인 명령은 다음과 같다.

```
SW1# show etherchannel summary
SW1# show etherchannel port-channel
SW1# show interfaces trunk
```

`show etherchannel summary`에서 Port-channel 옆의 플래그를 본다.

| 플래그 | 의미 |
|--------|------|
| SU | Layer 2 Port-channel이고 사용 중 |
| P | 포트가 Port-channel에 묶여 있음 |
| D | down |
| I | 독립 포트(묶이지 않음) |
| s | suspended (설정 불일치 등으로 중단) |

정상이면 `Po1(SU)` 옆에 `Gi0/1(P) Gi0/2(P)`가 나온다. 포트가 `I`나 `s`로 보이면 양쪽 모드 조합과 속도, 듀플렉스, VLAN 설정이 서로 같은지 확인한다.

## 확인 문제

1. 스위치 사이에 링크 두 개를 연결했을 때 STP만 쓰면 어떤 문제가 있는가?
2. EtherChannel이 프레임을 여러 링크로 나누는 방식은 무엇인가?
3. LACP에서 묶이지 않는 모드 조합은 무엇인가?
4. 한쪽이 `mode on`이고 반대쪽이 `mode active`이면 묶이는가?
5. `show etherchannel summary`에서 포트가 `I`로 나오면 무엇을 확인해야 하는가?

2. 출발지와 목적지 주소 등으로 해시를 계산해 프레임 단위가 아닌 플로우 단위로 포트를 고른다. 같은 조합은 항상 같은 포트로 나간다.
