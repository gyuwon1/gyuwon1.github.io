VLAN은 브로드캐스트 도메인을 나누므로 VLAN 10과 VLAN 20의 호스트는 같은 스위치에 있어도 직접 통신하지 못한다. 서로 다른 VLAN 사이의 통신은 3계층 장비가 라우팅해야 하며, 라우터와 트렁크 링크 하나로 이를 처리하는 방식이 Router-on-a-stick이다.

## VLAN마다 서브넷이 필요하다

VLAN 하나는 서브넷 하나에 대응한다. VLAN 10은 192.168.10.0/24, VLAN 20은 192.168.20.0/24처럼 나누고, 각 서브넷의 기본 게이트웨이는 라우터가 맡는다. 호스트는 목적지가 다른 서브넷이면 프레임을 게이트웨이로 보낸다.

라우터에 VLAN 수만큼 물리 포트를 연결해도 되지만 포트와 케이블이 VLAN 수만큼 든다. 스위치와 라우터 사이를 트렁크 하나로 잇고, 라우터의 물리 인터페이스 하나를 논리적으로 쪼개 쓰면 포트가 하나면 된다. 이 논리 인터페이스가 서브인터페이스다.

![PC1과 PC2가 SW1의 액세스 포트에 연결되고 SW1과 R1이 트렁크 링크 하나로 연결되며 R1의 Gi0/0에 VLAN 10, 20용 서브인터페이스가 있는 구성도]({{ '/assets/img/ccna/day15-roas-topology.svg' | relative_url }})

## 서브인터페이스

서브인터페이스는 `인터페이스이름.번호` 형식으로 만든다. 각 서브인터페이스에서 `encapsulation dot1q VLAN번호`로 어느 VLAN의 프레임을 받을지 지정하고, 그 VLAN 서브넷의 게이트웨이 IP를 붙인다.

![R1의 서브인터페이스 Gi0/0.10, Gi0/0.20, Gi0/0.99와 encapsulation, IP 주소, VLAN의 대응을 나타낸 표]({{ '/assets/img/ccna/day15-roas-subif.svg' | relative_url }})

- 물리 인터페이스 Gi0/0에는 IP 주소를 주지 않고 `no shutdown`만 한다
- 물리 인터페이스가 꺼져 있으면 서브인터페이스도 모두 동작하지 않는다
- 번호는 VLAN 번호와 맞추는 것이 관례다. 그래야 설정을 읽기 쉽다
- 네이티브 VLAN의 프레임은 태그가 없으므로 해당 서브인터페이스에 `encapsulation dot1q 99 native`를 쓴다. 네이티브 VLAN용 서브인터페이스를 따로 두지 않으면 태그 없는 프레임을 받을 곳이 없다

## 설정

라우터 쪽이다.

```
R1(config)# interface gigabitethernet0/0
R1(config-if)# no shutdown
R1(config-if)# interface gigabitethernet0/0.10
R1(config-subif)# encapsulation dot1q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# interface gigabitethernet0/0.20
R1(config-subif)# encapsulation dot1q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config-subif)# interface gigabitethernet0/0.99
R1(config-subif)# encapsulation dot1q 99 native
R1(config-subif)# ip address 192.168.99.1 255.255.255.0
R1(config-subif)# end
```

스위치 쪽은 R1과 연결된 포트를 트렁크로 만든다. Day 14의 설정과 같다.

```
SW1(config)# interface gigabitethernet0/1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
```

스위치의 네이티브 VLAN과 라우터의 `native` 서브인터페이스 번호가 같아야 한다. 어긋나면 Day 14에서 본 네이티브 VLAN 불일치와 같은 문제가 생긴다. 스위치 모델에 따라 `switchport trunk encapsulation dot1q`가 먼저 필요할 수 있다.

## 프레임이 지나가는 경로

PC1(VLAN 10)이 PC2(VLAN 20)에 보내는 경우를 따라간다.

![PC1의 프레임이 SW1에서 VLAN 10 태그를 달고 트렁크로 R1에 가고, R1이 VLAN 20 태그를 달아 같은 트렁크로 되돌려 SW1이 태그를 떼어 PC2에 전달하는 과정]({{ '/assets/img/ccna/day15-roas-path.svg' | relative_url }})

1. PC1은 목적지가 다른 서브넷이므로 ARP로 게이트웨이 192.168.10.1의 MAC 주소를 알아내고, 목적지 MAC을 R1으로 한 프레임을 보낸다
2. SW1은 VLAN 10 액세스 포트로 들어온 프레임에 VLAN 10 태그를 붙여 트렁크로 내보낸다
3. R1은 Gi0/0.10으로 프레임을 받아 태그를 떼고 라우팅 테이블을 조회한다. 192.168.20.0/24는 Gi0/0.20에 직접 연결되어 있다
4. R1은 PC2의 MAC 주소로 새 프레임을 만들고 VLAN 20 태그를 붙여 같은 물리 링크로 되돌려 보낸다
5. SW1은 VLAN 20 태그를 보고 VLAN 20의 액세스 포트로 내보내며 태그를 뗀다

IP 헤더의 출발지와 목적지 주소는 그대로이고 2계층 헤더의 MAC 주소와 태그만 바뀐다. 이 동작은 Day 12의 스위칭과 Day 21에서 배울 라우팅의 경계가 만나는 지점이다.

## 한계

모든 VLAN 간 트래픽이 하나의 물리 링크를 올 때와 갈 때 모두 지나간다. 링크 대역폭이 곧 VLAN 간 통신의 상한이 되고, 라우터의 처리 능력도 병목이 될 수 있다. 소규모나 시험용 구성에는 충분하지만 큰 망에서는 멀티레이어 스위치(3계층 스위치)가 SVI로 VLAN 간 라우팅을 맡는 방식이 많이 쓰인다. 이 방식은 `ip routing`을 켜고 `interface vlan 10`에 IP를 주는 식으로 설정하며, 스위치 내부에서 하드웨어로 처리된다.

## 확인 명령

```
R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0     unassigned      YES unset  up                    up
GigabitEthernet0/0.10  192.168.10.1    YES manual up                    up
GigabitEthernet0/0.20  192.168.20.1    YES manual up                    up
GigabitEthernet0/0.99  192.168.99.1    YES manual up                    up

R1# show ip route
C    192.168.10.0/24 is directly connected, GigabitEthernet0/0.10
L    192.168.10.1/32 is directly connected, GigabitEthernet0/0.10
C    192.168.20.0/24 is directly connected, GigabitEthernet0/0.20
L    192.168.20.1/32 is directly connected, GigabitEthernet0/0.20

SW1# show interfaces trunk
```

- `show ip interface brief`로 서브인터페이스의 IP와 상태를 확인한다
- `show ip route`에는 서브인터페이스마다 연결된 네트워크가 C로 올라온다. 게이트웨이 IP는 L(local) 경로로 함께 표시된다
- 통신이 안 되면 PC의 게이트웨이 주소, 트렁크의 허용 VLAN 목록, 서브인터페이스의 VLAN 번호, 물리 인터페이스의 `no shutdown`을 순서대로 본다

## 일본어 IT 용어

Router-on-a-stick은 「ルーター・オン・ア・スティック」로 쓰고 서브인터페이스는 「サブインターフェース」다. VLAN 간 라우팅은 「VLAN<ruby>間<rt>かん</rt></ruby>ルーティング」라고 한다. 한 링크에 트래픽이 몰리는 현상은 「<ruby>負荷<rt>ふか</rt></ruby>の<ruby>偏<rt>かたよ</rt></ruby>り」, 처리 능력은 「<ruby>処理<rt>しょり</rt></ruby><ruby>能力<rt>のうりょく</rt></ruby>」다. 두 VLAN 사이를 이어 주는 역할은 「<ruby>橋渡<rt>はしわた</rt></ruby>し」와 통한다. 이 단어들은 오늘 일본어 단어 글에 나온다.

## 확인 문제

1. Router-on-a-stick에서 라우터의 물리 인터페이스 Gi0/0에 IP 주소를 주는가?
2. 서브인터페이스 Gi0/0.30이 VLAN 30의 프레임을 받도록 하는 명령은?
3. 스위치에서 라우터와 연결된 포트는 액세스 포트와 트렁크 포트 중 무엇으로 설정하는가?
4. PC1(VLAN 10)이 PC2(VLAN 20)로 보내는 패킷에서 라우터를 지나는 동안 바뀌는 것과 바뀌지 않는 것은?
5. Router-on-a-stick의 가장 큰 단점은?

<details>

1. 주지 않는다. 물리 인터페이스는 `no shutdown`만 하고 IP 주소는 서브인터페이스에 준다.
2. `encapsulation dot1q 30`이다. 서브인터페이스 모드에서 입력한다.
3. 트렁크 포트다. 여러 VLAN의 프레임이 태그를 달고 지나가야 한다.
4. 2계층의 MAC 주소와 VLAN 태그는 바뀌고, IP 헤더의 출발지·목적지 주소는 바뀌지 않는다(TTL은 1 줄어든다).
5. 모든 VLAN 간 트래픽이 물리 링크 하나를 지나므로 대역폭과 라우터 처리 능력이 병목이 된다.
