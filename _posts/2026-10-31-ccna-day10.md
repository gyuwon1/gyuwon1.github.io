## 구간마다 바뀌는 주소

PC가 다른 네트워크의 서버로 보낼 때, 목적지 IP는 서버지만 목적지 MAC은 기본 게이트웨이(라우터)다. 같은 네트워크에 있지 않으면 PC는 서버의 MAC을 알 수 없고 알 필요도 없다. 라우터는 프레임의 L2 헤더를 벗기고, 목적지 IP로 경로를 찾은 뒤, 나가는 인터페이스에서 새 L2 헤더를 붙인다.

![라우터를 지나면서 MAC은 바뀌고 IP는 유지되는 모습]({{ '/assets/img/ccna/day10-hops.svg' | relative_url }})

스위치는 L2 헤더를 바꾸지 않고 MAC 주소 테이블로 전달만 한다. 구간마다 달라지는 것은 라우터를 지날 때뿐이다. NAT가 개입하면 IP도 바뀌지만, 이는 4부에서 다룬다.

## 서브넷 계산 순서

주소와 프리픽스가 주어지면 아래 순서로 푼다.

1. 마스크에서 값이 255가 아닌 옥텟을 찾는다. /26이면 네 번째 옥텟이 192다.
2. 블록 크기를 구한다. 256 - 192 = 64다.
3. 주소의 해당 옥텟이 속하는 구간을 찾는다. 77은 64~127 구간이다.
4. 구간의 시작이 네트워크 주소, 구간의 끝이 브로드캐스트 주소다.
5. 그 사이가 호스트 범위다. 호스트 수는 2의 n제곱 - 2다(n은 호스트 비트 수).

![192.168.10.77/26을 비트로 계산하는 과정]({{ '/assets/img/ccna/day10-subnet.svg' | relative_url }})

비트로 보면 AND 연산이 네트워크 주소를 만들고, 호스트 비트를 모두 1로 바꾸면 브로드캐스트 주소가 된다. 블록 크기 방식은 이 계산을 줄인 것이다. 시험에서는 손으로 빠르게 푸는 블록 크기 방식이 유리하다.

## 확인용 명령

1부에서 다룬 값은 PC에서 직접 확인할 수 있다. Windows 기준이다.

```
C:\> ipconfig /all
C:\> arp -a
C:\> netstat -an
C:\> tracert 10.0.0.20
```

`ipconfig /all`은 IP 주소, 서브넷 마스크, 기본 게이트웨이, MAC 주소를 보여 준다. `arp -a`는 IP와 MAC의 대응표다. 다른 네트워크 주소는 게이트웨이의 MAC으로 나가므로 서버의 MAC은 표에 나타나지 않는다. `netstat -an`은 열린 포트와 TCP 연결 상태를, `tracert`는 경유하는 라우터를 보여 준다.

## 확인 문제

1. PC가 다른 네트워크의 서버로 보내는 프레임의 목적지 MAC과 목적지 IP는 각각 누구의 것인가?
2. 172.16.45.9/20의 네트워크 주소와 브로드캐스트 주소는?
3. 172.32.1.1, 10.200.1.1, 192.169.0.1 중 사설 주소는?
4. SSH, HTTPS, DNS 질의가 기본으로 쓰는 포트와 전송 계층 프로토콜은?
5. 2001:0db8:0000:0000:0000:ff00:0042:8329를 가장 짧게 줄이면?

<details>
<summary>정답 보기</summary>

1. 목적지 MAC은 기본 게이트웨이(라우터)의 것이고, 목적지 IP는 서버의 것이다.
2. /20이면 세 번째 옥텟 마스크가 240이고 블록 크기는 16이다. 45는 32~47 구간이므로 네트워크 주소는 172.16.32.0, 브로드캐스트 주소는 172.16.47.255다.
3. 10.200.1.1뿐이다. 172.16.0.0~172.31.255.255가 사설 대역이라 172.32.1.1은 공인 주소이고, 192.169.0.1도 사설 대역(192.168.0.0/16) 밖이다.
4. SSH는 TCP 22, HTTPS는 TCP 443, DNS 질의는 UDP 53이다. DNS는 응답이 크거나 영역 전송일 때 TCP 53도 쓴다.
5. 2001:db8::ff00:42:8329다. 연속된 0 그룹 세 개를 ::로 줄이고 0db8과 0042의 앞 0을 지운다.
</details>
