3부는 라우팅이다. 스위치가 같은 네트워크 안에서 프레임을 전달했다면, 라우터는 서로 다른 네트워크 사이에서 패킷을 전달한다. 오늘은 라우터가 무엇을 보고 어디로 보낼지 정하는 과정을 본다.

## 라우터가 하는 일

라우터는 3계층 장비이다. 패킷의 목적지 IP 주소를 보고 라우팅 테이블에서 나갈 곳을 찾는다. 인터페이스마다 서로 다른 네트워크에 속하므로 라우터 한 대는 여러 브로드캐스트 도메인의 경계가 된다.

전달 과정은 다음 순서이다.

1. 프레임을 받아 이더넷 헤더를 벗기고 목적지 IP 주소를 읽는다
2. 라우팅 테이블에서 목적지와 가장 잘 맞는 항목을 찾는다
3. TTL을 1 줄인다. 0이 되면 패킷을 버린다
4. 다음 홉(또는 목적지 호스트)의 MAC 주소를 알아내 새 이더넷 헤더를 씌워 내보낸다

![PC1에서 PC2로 가는 패킷이 R1과 R2를 지날 때 MAC 주소와 TTL은 바뀌고 IP 주소는 유지되는 그림]({{ '/assets/img/ccna/day21-forward.svg' | relative_url }})

IP 주소는 출발지부터 목적지까지 그대로이고, MAC 주소는 구간마다 새로 쓰인다. 라우터 사이의 링크에서는 상대 라우터의 MAC 주소가 목적지가 된다.

## 라우팅 테이블

라우팅 테이블은 "이 목적지 네트워크는 이 방향으로 보낸다"는 항목의 모음이다. 항목은 세 방식으로 채워진다.

- 직접 연결된 네트워크: 인터페이스에 IP 주소를 설정하고 인터페이스가 up/up이면 자동으로 들어간다
- 정적 라우트: 관리자가 직접 입력한다
- 동적 라우팅 프로토콜: OSPF 같은 프로토콜이 이웃에게서 배운다

```
R1# show ip route
Codes: C - connected, S - static, L - local, O - OSPF
       * - candidate default

Gateway of last resort is not set

      10.1.1.0/24 is variably subnetted, 2 subnets, 2 masks
C        10.1.1.0/24 is directly connected, GigabitEthernet0/0
L        10.1.1.1/32 is directly connected, GigabitEthernet0/0
S     10.3.3.0/24 [1/0] via 192.168.12.2
O     10.2.2.0/24 [110/2] via 192.168.12.2, 00:05:12, GigabitEthernet0/1
```

항목 앞의 글자는 경로를 알게 된 방법이다. C는 연결된 네트워크, L은 라우터 자신의 인터페이스 주소(/32)이다. S는 정적, O는 OSPF이다. 대괄호의 두 숫자는 앞이 AD(신뢰도), 뒤가 메트릭이며 다음 날 자세히 다룬다. via 뒤의 주소가 다음 홉이고, 마지막의 인터페이스 이름이 나가는 인터페이스이다.

## 가장 긴 프리픽스 일치

목적지와 일치하는 항목이 여러 개이면 프리픽스 길이가 가장 긴 항목을 고른다. 더 구체적인 경로가 우선이라는 뜻이다.

![목적지 10.1.2.5에 대해 /8, /16, /24, /0 항목이 모두 일치하고 /24가 선택되는 표]({{ '/assets/img/ccna/day21-match.svg' | relative_url }})

일치하는 항목이 하나도 없으면 라우터는 패킷을 버리고 보통 ICMP 목적지 도달 불가 메시지를 돌려보낸다. 0.0.0.0/0 항목(디폴트 라우트)이 있으면 어떤 목적지도 최소한 이 항목에는 일치하므로 버려지지 않는다. 디폴트 라우트는 다음 날 설정해 본다.

## 일본어 IT 용어

라우팅 테이블은 「ルーティングテーブル」, 다음 홉은 「ネクストホップ」, 디폴트 라우트는 「デフォルトルート」라고 한다. 경로 자체는 「<ruby>経路<rt>けいろ</rt></ruby>」, 패킷이 지나가는 길은 「<ruby>道筋<rt>みちすじ</rt></ruby>」라고도 한다. 「<ruby>経路<rt>けいろ</rt></ruby>を<ruby>確認<rt>かくにん</rt></ruby>する」는 show ip route 같은 명령으로 경로를 보는 일에 쓴다. 오늘 일본어 단어 글에는 「<ruby>道筋<rt>みちすじ</rt></ruby>」, 「<ruby>行<rt>ゆ</rt></ruby>き<ruby>先<rt>さき</rt></ruby>」, 「<ruby>中間<rt>ちゅうかん</rt></ruby>」처럼 이 주제와 이어지는 단어가 나온다.

## 확인 문제

1. 라우터가 패킷을 전달할 때 바뀌지 않는 헤더 정보는 무엇인가?
2. show ip route에서 코드 L은 무엇을 뜻하는가?
3. 라우팅 테이블에 10.0.0.0/8과 10.1.2.0/24가 모두 있을 때 목적지 10.1.2.7은 어느 항목으로 전달되는가?
4. 패킷의 TTL이 라우터에서 줄여서 0이 되면 어떻게 되는가?
5. 라우팅 테이블에 일치하는 항목이 없고 디폴트 라우트도 없으면 어떻게 되는가?

1. 출발지와 목적지 IP 주소이다. MAC 주소는 구간마다 새로 쓰이고 TTL은 1씩 줄어든다.
2. 라우터 자신의 인터페이스 IP 주소를 나타내는 로컬 라우트이다. /32 호스트 경로로 표시된다.
3. 10.1.2.0/24이다. 두 항목 모두 일치하지만 프리픽스가 더 긴 쪽이 선택된다.
4. 패킷을 버리고, 보통 출발지에 ICMP 시간 초과 메시지를 보낸다.
5. 패킷을 버리고, 보통 출발지에 ICMP 목적지 도달 불가 메시지를 보낸다.
