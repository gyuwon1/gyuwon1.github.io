# 자동 포스팅 규칙

매일 오전 9시~오후 8시(KST) 사이의 임의 시각에 예약 작업이 새 글 2개를 `_posts/`에 추가하고 커밋·push 합니다.
시각은 하루 전에 이전 실행이 랜덤으로 정해 예약합니다. 오후 8시 10분에는 점검 작업이 한 번 더 돌아서, 그날 글이 없으면 대신 올리고 다음 날 예약이 있는지 확인합니다.

## 글 말투 (일본어·CCNA 공통)

공부 노트처럼 간결한 평어체("~이다", "~한다")로 쓴다.

- "~입니다 / ~해요 / ~해보세요" 같은 존댓말과 강의 말투("다음 시간에는") 금지
- 글머리에 소개, 인사, 안내 문장을 쓰지 않는다. 바로 본문(표 또는 첫 소제목)으로 시작한다
- "학습 목표", "핵심 개념", "핵심 정리" 같은 틀에 박힌 제목 금지. 소제목은 짧게 (예: "LAN과 WAN")
- 굵은 글씨, 이모지, 느낌표를 쓰지 않는다. 꾸미는 말과 감탄 표현도 뺀다
- 항목을 나열할 때는 목록을 쓰고, 설명은 짧은 문장으로 쓴다
- 비유는 한두 개만 쓴다
- 실제로 겪지 않은 경험담(회사, 학원 에피소드 등)을 지어내지 않는다
- 일본어 글 끝의 활용 팁 섹션도 같은 평어체로 쓴다. 제목은 "업무에서 자주 쓰는 표현"처럼 담백하게

## 일본어 단어 글

- 파일명: `_posts/YYYY-MM-DD-japanese-vocab-dayN.md`
- front matter: `categories: [japanese]`, 제목 `일본어 단어 Day N`
- JLPT N2 수준 단어 30개를 표로 작성: `# | 한자 | 히라가나 | 뜻 | 예문` (예문 아래 `<br>`로 한글 번역)
- **예문 속 모든 한자에 후리가나**를 `<ruby>漢字<rt>かんじ</rt></ruby>` 형식으로 단다. 오쿠리가나는 ruby 밖에 둔다 (예: `<ruby>取<rt>と</rt></ruby>る`). 글을 쓴 뒤 후리가나가 빠진 한자가 없는지 확인한다.
- **복습 규칙**: 30개 중 5~10개는 바로 직전 회차(어제 글)의 단어를 다시 넣고, 번호 칸에 `(복습)`을 붙인다. 복습 단어에는 어제와 다른 새 예문을 쓴다.
- 나머지 단어는 지금까지 나온 모든 단어와 겹치지 않아야 한다. 복습으로 한 번 더 나온 단어는 다시 쓰지 않는다.
- 새로 쓴 단어는 `automation/vocab_log.md`에 그날 줄을 추가해 기록하고, 중복 확인에도 이 파일을 쓴다.
- 끝에 짧은 활용 팁(실제로 쓰이는 표현) 한 문단을 붙인다.

## CCNA 글

- 파일명: `_posts/YYYY-MM-DD-ccna-dayN.md`
- front matter: `categories: [ccna]`, 제목 `CCNA Day N: 주제`
- `automation/ccna_curriculum.md`의 다음 주제를 순서대로, 기초부터 20~30분 분량으로 작성한다.
- **그림을 반드시 넣는다**: 그날 주제에 맞는 구성도, 흐름도, 패킷 구조, 표 등을 직접 SVG로 그려 `assets/img/ccna/dayN-이름.svg`에 저장하고, 글에는 `![설명]({{ '/assets/img/ccna/dayN-이름.svg' | relative_url }})`로 넣는다. 보통 2~3장.
  - SVG는 `viewBox`, `<title>`, `<desc>`를 넣고 흰 배경 사각형을 깐다. 글자는 `font-family: "Noto Sans KR", "Malgun Gothic", sans-serif`.
  - 그림은 실제 동작 원리가 보이게 그린다 (장식용 금지). 글자가 겹치지 않는지 좌표를 확인한다.
  - 외부 이미지는 가져오지 않는다 (저작권).
- 구성 흐름: 도입 한두 문장 → 주제 설명(그림 포함) → 명령어나 예시가 있으면 코드 블록 → 일본어 IT 용어 한 문단 → 확인 문제 5개(정답은 `<details>`로 접기) → 내일 주제 한 줄
- 기술 내용은 정확해야 한다. 확실하지 않은 사실은 쓰지 않는다.

## 공통

- 날짜 front matter는 글을 쓰는 **현재 시각**을 `YYYY-MM-DD HH:MM:00 +0900` 형식으로 쓴다. 미래 시각은 Jekyll이 게시하지 않으므로 쓰지 않는다.
- 같은 날짜의 글이 이미 있으면 새로 만들지 않는다
- 커밋 메시지: `Add posts for YYYY-MM-DD`

## 일일 포스팅 절차 (예약 작업이 따르는 순서)

1. `TZ=Asia/Seoul date`로 오늘 날짜와 현재 시각을 확인한다. 오늘 날짜(KST)의 글이 `_posts/`에 이미 있으면 글은 새로 만들지 않고 4번으로 간다.
2. 위 규칙대로 일본어 글과 CCNA 글을 쓴다 (그림, 후리가나, 복습 단어, `vocab_log.md` 기록 포함).
3. main에 커밋하고 push한다.
4. **다음 날 예약 확인·생성**: `list_triggers`로 이름이 `학습 블로그 포스팅 YYYY-MM-DD` (날짜는 예약 대상일)인 예약이 이미 있는지 본다. 없으면 `create_trigger`로 만든다.
   - `run_once_at`: 내일(KST) 09:00~20:00 사이의 임의 시각. python `random`으로 분 단위로 뽑고, UTC(RFC3339, `Z`)로 변환해서 넣는다.
   - `name`: `학습 블로그 포스팅 YYYY-MM-DD` (날짜는 예약 대상일), `initiation`: `human_schedule`, `notifications`: `{"push": true}`
   - `prompt`: 이 예약 작업 자신의 프롬프트와 같은 내용 (저장소 clone → 이 README의 일일 포스팅 절차를 따른다).
5. 마지막에 오늘의 Day 번호, CCNA 주제, 복습 단어 개수, 다음 예약 시각을 한 줄로 보고한다. push나 예약 생성이 실패하면 원인을 그대로 보고하고 재시도 루프를 돌지 않는다.
